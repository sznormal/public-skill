# P5 · 可发表性评分（带否决开关）

> 目标：把"这题好不好"变成结构化讨论。**分数暴露薄弱环节，不替代导师判断。**

## 一、8 维评分卡

| 维度 | 权重 | 打分依据（可操作化） |
|---|---:|---|
| 空白真实性 | 20% | 六重门 A–C 全过才给 70+ |
| 重要性 | 15% | **能点名 3 个会引用它的团队/场景**，说不出来 ≤50 |
| 新颖性（最近邻差异） | 15% | 与最近 3 篇的差异能用一句话讲清 |
| 机理深度 | 10% | 不仅有性能提升，还能解释"为什么提升" |
| 可行性 | 15% | 数据/设备/算力/周期四项，每缺一项扣 25 |
| 可验证性 | 10% | 有公认基线 + 公开数据 + 客观指标 + 消融设计 |
| 期刊匹配与撞题 | 10% | 目标刊近 3 年持续发同主题；撞题风险低 |
| 退路设计 | 5% | 核心假设被证伪后，副产物能否支撑转向 |

参考线：**≥70 可开题，≥80 优先**。但先过否决规则。

## 二、否决规则（本方法论的实质增量，不可跳过）

1. **任一维度 < 50 → 整体否决**，不看总分。
   理由：加权平均会掩盖致命项——真实性 40 分、其他全 90，总分仍能过线，然后你死在一篇三个月前上传的预印本上。
2. **空白真实性 < 70 → 直接否决**，其他项再漂亮也不开题。
3. **导师与学生独立打分，单项分歧 > 20 分必须重议**——这一条让评分卡从自欺工具变成真工具。

## 三、脚本计算

```bash
python scripts/score_topic.py outputs/topic-selection/scorecard.json
```

- 输入：含 `scores`（0–100）与 `weights` 的 JSON；支持两份独立打分（`scores_advisor`）自动算加权分并检测分歧；
- 输出：加权总分、逐维明细、**是否触发否决**、否决原因、双人分歧 >20 的维度清单；
- 退出码：0 = 通过，1 = 触发否决，2 = 输入不完整。

⚠️ 脚本只做算术与规则判定，**不给建议改哪个维度**——那需要人来判断。

## 四、产出

- `outputs/topic-selection/scorecard.md`（含 8 维分、加权总分、否决检查、双人打分对照）
- `outputs/topic-selection/scorecard.json`（脚本输入，可复跑）

## 五、Hard Stop

向用户确认：
1. 每一维的打分**依据是什么**（不能只给数字）；
2. 师生双人打分的分歧维度有哪些 → 分歧 >20 的必须重议，别带着分歧进 P6；
3. 是否触发否决 → 触发则回 P3 补料或换题，**不要靠调分数过关**（调分数是这套机制失效的第一信号）。

## 六、常见坑

- ❌ 单人打分自评自过 → 双人是硬要求；
- ❌ 为了过线把某维从 45 调到 55 → 等于关掉否决机制；
- ❌ "重要性"凭感觉给高分 → 判据是**能点名 3 个使用者/引用者**，说不出就 ≤50；
- ❌ 打完高分就开工 → 分数只是入场券，P6 的 MVP 才是真正的风险闸。
