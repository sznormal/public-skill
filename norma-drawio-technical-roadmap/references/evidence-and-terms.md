# 证据链与术语规范

S3 提炼资料时加载本文件。解决两个问题：图上的内容能不能溯源、术语在全图是否统一。

## 一、节点清单 schema

`02-内容结构.md` 用一张表承载全部节点，逐列填写：

| 列 | 填什么 | 示例 |
|---|---|---|
| 层级 | 分区 / 阶段 / 卡片 / 说明 | 阶段 |
| 节点文字 | 最终写进图上的文字，4—18 字 | 成像系统选型与数据采集 |
| 类型 | 标题条 / 普通卡片 / 强调卡片 / 说明框 | 标题条 |
| 来源 | 资料名 + 章节、页码或行号 | 《申报书》三（一）2 |
| 状态 | `verified` / `unverified` / `待补充` | verified |
| 备注 | 冲突、归纳说明、待用户确认的点 | 原文为「图像获取系统」，按术语表统一 |

同表下方附「术语一致性表」与「冲突与缺项记录」两节。

## 二、来源标注规则

- 每个节点必须填「来源」。资料是 PDF 或 Word 时写章节与页码；是文本要点时写段落序号或原文片段。
- 同一来源覆盖多个节点时逐行重复写明，不写「同上」。
- 归纳而来的节点仍要标出原始出处，并在备注写「由 X 与 Y 归纳」。
- 无任何依据、由常识补全的内容一律不允许；确实需要占位时写 `待补充`，不得写推测值。
- 图上出现指标、数量、百分比、时间点等数据类内容时，来源列额外标注采集或统计时间，格式 `来源（时间）`。无法确认时间的标 `unverified`。

## 三、状态判定

| 状态 | 判定条件 | 图上的处理 |
|---|---|---|
| `verified` | 资料中有明确原文 | 正常出图 |
| `unverified` | 有出处但无法确认口径、时间或数值 | 正常出图，在 `02-内容结构.md` 标记，节点文字不加标记 |
| `待补充` | 资料完全没有 | 图上写「待补充」，不用常识填空 |

`unverified` 与 `待补充` 的总数写入 `manifest.json` 的 `notes`，交付时用户能一眼看到。

## 四、术语一致性表

| 术语 | 图中统一写法 | 资料中的其他写法 | 出现位置 |
|---|---|---|---|
| 机器视觉 | 机器视觉 | 计算机视觉、工业视觉 | 阶段一标题条、阶段二卡片 |

规则：

- 同一概念在全图只保留一种写法，先填表再生图，不要边画边改。
- 统一写法优先采用资料中出现次数最多、或最正式的那一种。
- 专有名词、缩写、设备型号、软件名、算法名保持原文大小写与连字符，不翻译、不简写。
- 资料本身混用时，按「最正式来源优先」选定，并在备注记录冲突。

## 五、归纳边界

| 可以做 | 不能做 |
|---|---|
| 长句压成 4—18 字短语 | 改变原意或改变范围 |
| 合并重复出现的内容 | 合并两个不同阶段的任务 |
| 拆分过长的复合任务 | 自行新增资料里没有的阶段 |
| 统一术语写法 | 把「计划」写成「已完成」 |

## 六、常见坑

- **把申报书的「预期成果」当成「已完成」**：图上时态按资料原文，不升级。
- **指标数字跨单位混用**：同一张图内单位统一，来源不同导致单位不同时在备注写明。
- **阶段编号跳跃**：阶段序号连续，缺号时在备注说明。
- **把参考文献当研究内容**：文献是手段不是内容，不进节点清单。
