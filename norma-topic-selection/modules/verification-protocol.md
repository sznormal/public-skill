# 模块 · 六重门验伪协议

> P3 调用。**空白是"验"出来的，不是"找"出来的。** 本模块给每道门提供可执行动作与留档格式。

## 一、门 A：检索完备性

**目标**：排除"检索偏差造成的假空白"。

必须构造 **3 组检索式**，不是 1 组：

| 组 | 构造方式 | 例（以"跨设备少样本检测"为例） |
|---|---|---|
| ① 同义词与缩写 | 同一概念的多种说法 | cross-device / device-invariant / domain-agnostic / OOD detection |
| ② 上下位词 | 上位词 + 下位词 | few-shot detection / low-data learning / transfer detection |
| ③ 问题表述 | 不用术语、用意图句 | without retraining / calibration-free / zero adaptation |

- 跨库：按领域选 WoS / Scopus / IEEE Xplore / ACM DL / Google Scholar / arXiv / CNKI / 专利与技术报告库；
- 中英文双轨；
- **不止查"相同题目"**：要查"**同一问题的不同术语表述**"——大量漏检来自术语不统一；
- 留档：每组检索式 + 数据库 + **检索日期** + 命中数。

**判废**：只搜一个库、或只搜一种表述得出的"空白"，一律记为 `待定`。

## 二、门 B：在研与抢发

**目标**：抓"别人正在做"和"已被预印本抢占"。

| 查什么 | 去哪查 | 时间窗 |
|---|---|---|
| 预印本 | arXiv、SSRN、Research Square | 最近 12–18 个月 |
| 会议在投/已录用 | 各大会议近 12 个月 accepted list、近 12 个月 workshop 摘要 | 近 12 个月 |
| 团队动向 | 主要团队主页、实验室主页、GitHub 活跃仓库 | 持续 |

**留档字段**：命中论文/条目、ID（arXiv 号/DOI）、日期、与本候选的差异。

**判据**：若已有工作**问题相同、方法不同** → 你要评估是"可跟进改进"还是"换角度"；若**问题与方法都相同** → 立即换题。

⚠️ 撞题是**动态风险**：P7 阶段仍需**按月复跑本门**。

## 三、门 C：最近邻与反证

**目标**：证明新颖性，并主动找推翻自己的证据。

### C1 最近邻比较（3–5 篇）

选"最近邻"而非"完全相同"：问题/场景/方法/数据中至少一项高度接近。

比较维度固定 8 项：研究问题、场景条件、数据/设备、方法、对照实验、指标、主要贡献、尚未解决之处。

**判据**：只有与最近邻存在**清晰、实质的差异**（换数据集不算），才具备新颖性。

### C2 反证清单（逐条书面回答，不得跳过）

1. 是否已有同类方法发表？（→ 回门 A 换词再查）
2. 是否已有相同数据与实验设置？（→ 你的实验设计还有新意吗）
3. 是否有工作证明**这个问题影响很小**？（→ 重要性存疑，回 P4 重要性判据重打分）
4. 是否有人尝试过但因技术原因失败？（→ 是风险信号，写进 P6 退路）
5. 是否只是因为检索范围太窄才看起来没有研究？（→ 假空白）

**"没有找到反例"不是结论；"主动找过反例后仍成立"才是。**

## 四、门 D：真人确认

**目标**：捕获检索不到的"圈内进行中工作"。

- 对象：导师 + 1–2 位近 3 年在该主题发过论文的作者；
- 问法（不要问"这题有人做吗"这种诱导性问法）：
  - "这个场景/问题，贵组最近有人在推进吗？"
  - "如果我做这个方向，你觉得最大的坎在哪？"
  - "有没有推荐的近期工作我该读？"

**⚠️ 纪律**：专家意见是**参考性证据，不是决定性证据**。

| 专家说法 | 处置 |
|---|---|
| "有人做" | 触发门 B 复查（去查是否真的在投稿），**不直接换题** |
| "没人做，但难" | 正面信息，进 P6 退路设计 |
| "没听说过" | 只说明圈内不活跃 → 回门 A 查是否术语不统一 |

## 五、门 E：撞题与承接

**目标**：避免 desk reject，并确认期刊**接得住**这种研究。

逐刊查 3 项：

1. **撞题**：近 3 年目录中该刊是否发过同题/高度相似工作？
2. **承接**：该刊近 3 年是否**持续**发这个主题？（有活跃审稿人池 = 接得住）
3. **偏好**：常见论文偏方法/应用/理论/数据集？实验规模是否与你相当？

**留档**：刊名、检索式、检索日期、命中文章列表与差异说明。

**按月复跑**：P7 阶段仍需执行本门。

## 六、门 F：可行性与机理

### F1 可行性四项打勾（缺一即为赌）

| 项 | 判据 | 缺项后果 |
|---|---|---|
| 数据 | 公开可获取，或已获得授权与渠道 | 几个月后发现拿不到，题作废 |
| 设备 | 实验室有，或可稳定借用/租用 | MVP 卡死 |
| 算力 | 估算过峰值，能排队到 | 后期无法训练/复现 |
| 周期 | 与学位时间线匹配（留缓冲） | 做不完，风险由个人承担 |

### F2 机理自洽（理工科强约束）

回答：你的改进能解释"**为什么提升**"吗？

| 层级 | 证据 | 是否合格 |
|---|---|---|
| 最高 | 物理定律/数学推导给出界或闭式解 | ✅ |
| 中 | 因果机制清晰 + 充分消融验证 | ✅ |
| 低 | 只有相关性/经验观察 | ⚠️ 降级为工程开发 |
| 无 | 说不清 | ❌ 改做实证/约束空白 |

## 七、核验记录格式（`gate_record.md` 逐门留档）

```markdown
## 门 X · 名称
- 执行日期：
- 动作（具体做了什么）：
- 检索式 / 检索式来源：
- 命中与关键发现：
- 结论：真 / 伪 / 待定
- 留档（链接/文件）：
- 下一步动作：
```

**门门留档是本阶段唯一有价值的产物**——导师质疑时，你能指着记录说"这一门是这么过的"，而不是"我感觉没人做过"。
