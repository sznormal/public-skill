# Stage 子文档模板（Pattern 5）

> AFP Skill Creator · Template
> 使用：你创建的 skill 的每个 stages/NN-xxx.md 都复制本模板填写——保证全 skill 步进纪律统一
> 规范依据：stages/06-content-writing.md §三（六要素落实到单个 stage 的标准骨架）

---

## 模板正文（从下一行开始复制）

```markdown
# P{N} · {阶段名}

> {skill 中文名} · Stage {NN}
> 目的：{本阶段一句话目的——从方法论显性化五问的"步骤"里来}

---

## 一、本阶段做什么（边界声明）

本阶段只产出 **{X}**。

不做：{后续阶段的事 1}（P{M} 的职责）/ {后续阶段的事 2}（P{K} 的职责）。
用户在本阶段要求越阶产出时，说明边界并引导回当前任务。

---

## 二、引导逻辑

### 2.1 启动检查

- 前置条件：{P{N-1} 的产出 X 已确认}（HUD 中 `stages.P{N-1}.status == done`）
- 需要用户提供：{本阶段新输入，没有则写"无"}

### 2.2 执行步骤

1. {动作 1：提问 / 分析 / 生成什么}
2. {动作 2}
3. {动作 3}

### 2.3 完成判断标准

{本阶段怎么算做对了——来自方法论五问的"问 3"。例：主题矩阵至少覆盖 3 个维度且互斥}

达不到标准时：{补救动作，如"报告缺口并引导用户补充材料，不硬编"}

---

## 三、方案型决策点（如有，无则删除本节）

**决策：{要拍板什么}**——不替用户拍板，输出：

```
方案 A：{描述} —— 优势：{...} / 代价：{...}
方案 B：{描述} —— 优势：{...} / 代价：{...}
👉 请选择：A / B（或说出你的调整）
```

选定后写入 HUD `decisions.{key}` 并落盘。

---

## 四、输出 schema

本阶段产出物结构：

```
{字段 / 章节 / 格式定义。例：
## 主题矩阵
| 主题 | 定义 | 支撑编码 | 反例检查 |
每行必填；无法验证的条目标 unverified}
```

落盘路径：`{project_path}/stage-outputs/p{N}-{name}.md`

（有独家语料时保留本段）**few-shot 校准**：生成前 Read `modules/exemplars.md` §{对应节}的 90 分样例，对齐其结构、颗粒度与行文手感；输出后对照样例自检一遍再交付。

---

## 五、Hard Stop · 交付确认单

```
╭─ {skill 中文名} · P{N} {阶段名} 完成 ──────────╮
│ 📊 {关键状态字段 1}：{值}
│ ✅ 产出：stage-outputs/p{N}-{name}.md · 💾 状态已写盘
│ {🔀 本阶段决策：{用户选了什么}}
│ 📍 下一步：P{N+1} - {下一阶段名}
│ 👉 NEXT：Next 继续 / Back 回退 / Edit 修改
╰──────────────────────────────────────────╯
```

**即使结果非常明确，也不允许自动进入下一阶段。**

---

## 六、反模式警告

本阶段易错点（从方法论五问的"失败点"里来，3-8 条）：

- ❌ {失败点 1：症状 + 一句防御}
- ❌ {失败点 2}
- ❌ {失败点 3}

---

*P{N} 完成后，主控加载 stages/{NN+1}-{next-name}.md*
```

（模板结束；最后一个 stage 的脚注改为："*P{N} 是最后一个阶段，完成后输出全流程交付确认单*"）

---

## 使用检查清单（每写完一个 stage 过一遍）

- □ 无 frontmatter？（子文档铁律）
- □ 边界声明写了"只产出什么 + 不做什么"？
- □ 完成判断标准可检查（不是"写得好"这种没法判的标准）？
- □ 确认单格式与主控 §Hard Stop 输出规范完全一致？
- □ "不允许自动推进"条款在？
- □ 路由脚注指向的文件真实存在？
- □ 1500-4000 token 内？超了就把辅助内容拆去 modules/
