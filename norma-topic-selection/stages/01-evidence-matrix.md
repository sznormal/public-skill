# P1 · 证据矩阵

> 目标：把"我读过"变成"我看得见"——**不建矩阵，空白就永远只是印象**。

## 一、硬性门槛

- 建议 **≥40 行**（文献条数）；**少于 20 行时看到的"空白"很可能只是读得不够**，先回去读。
- 按"问题—方法—证据—边界"拆解，**不要按论文顺序做摘要**。
- 每一格的结论必须能追到原文；无出处的一律留空标 `待核`，**助手不得代填**。

## 二、字段（12 列）

| 类别 | 字段 | 填法要点 |
|---|---|---|
| 研究问题 | `problem` | 论文试图解决什么（不是它用了什么模型） |
| 方法 | `method` | 核心方法/模型/算法/实验方案 |
| **机理** | `mechanism` | 方法成立的物理、数学或因果前提（V4 增补；空则说明可能是纯拼装） |
| 数据/设备 | `data` | 数据集、传感器、实验平台、样本规模 |
| 场景条件 | `scenario` | 仿真/实验室/真实环境/边缘设备/产线 |
| 对照方法 | `baseline` | 与哪些基线比 |
| 评价指标 | `metrics` | 精度/鲁棒性/延迟/能耗/成本/标注量 |
| 主要结论 | `claim` | 作者声称取得的效果（含数值，勿概括） |
| 证据强度 | `strength` | 单实验 / 多数据集 / 跨场景 / 公开代码 |
| 局限性 | `limitation` | 摘**原文** |
| 未验证条件 | `unverified` | 哪些条件没被测（真实环境、跨设备、少样本、OOD、低算力…） |
| 可复现性 | `repro` | 数据/代码/参数/设备是否公开 |

## 三、三个挖掘动作

1. **看稀疏列**：哪种指标或工况在绝大多数文章中是 `—` 的？（如"论文都报精度、极少报延迟/能耗/内存"）
2. **看矛盾格**：标出结论相反的文献对，逐对判断冲突来源（数据集/条件/指标/参数/实现版本/研究质量）。**能解释矛盾来源 → 高价值证据型选题**。
3. **看孤证区**：只有一篇文献提出、缺乏独立验证的结论。

## 四、脚本体检（P1 收尾必跑）

```bash
python scripts/matrix_lint.py outputs/topic-selection/evidence_matrix.md
```

输出：总行数、必需列缺失项、**稀疏列清单**、矛盾标注对数、孤证条目数、是否达到 40 行门槛。
脚本只做机械统计，**不判断空白是否成立**。

## 五、产出

- `outputs/topic-selection/evidence_matrix.md`（含 12 列表头 + 每行一条文献）

## 六、Hard Stop

向用户报告并确认：
1. 矩阵行数与稀疏列（哪些条件/指标几乎没人做——这是候选矿脉的坐标）；
2. 矛盾格有哪几对（若有，优先挑可解释冲突来源的做证据型选题）；
3. 孤证区有哪几条。
用户确认后进入 P2。

## 七、常见坑

- ❌ 把 40 行写成 40 段摘要 → 字段不填满，矩阵就没有筛选价值；
- ❌ 数据集只写名字不写规模 → 跨论文比较时无法判断可比性；
- ❌ `limitation` 只写自己翻译的一句话 → 抓原文，措辞差异会带出真实痛点；
- ❌ 只填对自己有利的行 → 矛盾格与孤证区恰恰是选题金矿，漏了等于放弃最好的空白类型。
