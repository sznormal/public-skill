# P7 · 质量审核

> Norma理工科文献综述 · Stage 07
> 前置条件：P6 参考文献真实性核验必须已通过（gate_passed = true），否则本阶段
>            的"达到提交标准"结论一律为"否"。
> 目标：从技术准确性、逻辑完备性、引用规范性三个维度审核综述初稿

---

## 一、技术准确性审核

### 1.1 事实核查
- 每篇文献的核心贡献描述是否准确？（对照 P3 的摘要信息交叉验证）
- 技术术语使用是否正确？（缩写展开、领域专有名词）
- 性能数据引用是否与原文一致？

### 1.2 理工科专项
- 硬件参数/实验设置描述是否精确？（电压、频率、芯片型号等）
- 数学符号/公式引用是否正确？
- 图表引用编号是否与实际对应？

---

## 二、逻辑完备性审核

### 2.1 结构检查
- [ ] 各章节之间有逻辑递进（不是罗列）
- [ ] 每段有明确主题句
- [ ] 段末有承上启下或总结
- [ ] "现有工作不足"部分有足够论据支撑

### 2.2 覆盖度检查
- [ ] P3 的每个聚类主题是否在综述中有对应章节？
- [ ] 核心文献（`[CORE]`、`[FOUNDATION]`）是否全部覆盖？
- [ ] 时间覆盖是否均衡？（不能只有近两年的，也不能只引老文献）

### 2.3 理工科特有陷阱
- ❌ **"技术决定论"**：暗示某方法"完全解决了"某问题（工程问题很少有完全解决一说）
- ❌ **"苹果比橙子"**：不同实验条件下的结果直接比较
- ❌ **过时结论**：引用已被后续工作推翻的结论而未说明
- ❌ **忽视实际约束**：只讨论精度，不谈实时性/功耗/成本——这在嵌入式领域是致命漏洞

---

## 三、引用规范性审核

> 前提：参考文献的**真实性**已由 P6 核验（gate_passed = true）。本阶段只检查
> 引用在"正文—列表"之间的一致性与格式，不再重复核验真实性。若 P6 未通过，
> 本阶段"达到提交标准"直接判"否"。

### 3.1 引用完整性
- [ ] 正文中每处引用在参考文献列表中都有对应条目
- [ ] 参考文献列表中每条在正文中都被引用
- [ ] 参考文献格式统一（GB/T 7714 或 IEEE）

### 3.2 引用合理性
- [ ] 关键论断有引用支撑（无凭空断言）
- [ ] 优先引用原始文献而非二次引用
- [ ] 自引比例不过高（<20%）

### 3.3 论断-证据一致性审核（证据核查，全类型必做）

> 依据 `modules/evidence-mapping.md`，核查 P5 落盘的 `claim_evidence_map.md`：

- [ ] **无据论断清零**：正文中不存在未入映射表的判断句；E0 论断已删除或显式标注为展望
- [ ] **强度-措辞匹配**：E2/E3 证据未使用 E1 措辞（"已证明/已成为主流/广泛验证"）
- [ ] **孤证已披露**：⚠️ 孤证论断在正文中有显式限定（"有研究初步表明…"）
- [ ] **证据基座核对**：每章首段的文献数与核心文献标注，与 P3 聚类/P4 大纲一致
- [ ] **方法学留痕可追溯**：`search_log.md`（检索日志+召回率）、`screening_decisions.md`
  （筛选留痕，含 P3 选文确认的用户确认/增删记录）存在且与正文方法节/局限节的说法一致

> 任一项不过 → 记为"一般"或"严重"问题；无据论断未处置 → **严重**，"达到提交标准"判否。

---

## 三-B、按 review_type 分支的审核维度

在通用三维度（技术 / 逻辑 / 引用）之外，按类型追加：

- **T1**：重点查"是否流水账、缺口是否有据、有无越权声称 systematic"。
- **T2**：**必查** PRISMA 2020 流程图完整性 + 偏倚风险评估表存在性 + 预注册声明；任一缺失 → "达到提交标准"判否。
- **T3**：查是否**越界**做因果 / 理论综合（scoping 不做）；查 PRISMA-ScR 清单。
- **T4**：**必查** 图表数据来源可追溯 + 清洗规则明确 + 突现词方法说明。
- **T5**：查论点是否有证据支撑、是否过度主张（overclaim）。

## 三-C、字数闸门（按 review_type，P0 已定目标）

> 终审前强制统计终稿字数，对照 P0 锁定的 `draft.word_count_target`（中英双口径）。
> 统计范围：正文（含图表标题与公式，不含摘要 / 参考文献 / 致谢）。

> **🔴 口径统一（2026-09-07 修正）**：中文一律按 **汉字数（CJK 字符数，不含标点、不含空白、
> 不含 markdown 标记）**，与 `modules/review-types.md` 保持一致；英文按 **word**。
>
> **缺陷说明**：旧版本阶段写的是"中文按『字』（**含标点**）"，与 `review-types.md`
> 的"**汉字数**"直接冲突。两口径差值可达 2 倍以上（实测某稿：汉字数 **5,518** vs
> 全部字符 **12,608**），按"含标点"口径会把**严重偏短**的稿件误判为 PASS。
> 现统一为**保守口径（汉字数）**。
>
> 若目标期刊"作者指南"按版面字数（含标点）计，则**两个值都记入报告**，
> 但**判级一律以汉字数为准**；仅当汉字数达标后，才在报告附注期刊口径值。

### 字数核查步骤
1. **必须用脚本实测，禁止目测或沿用历史值**（历史 HUD 值常混入"全部字符"口径）：

   ```
   python -c "import re;t=open('<draft>',encoding='utf-8').read();b=t.split('## 参考文献')[0];print('汉字数:',len(re.findall(r'[\u4e00-\u9fff]',b)),'| 英文词:',len(re.findall(r'[A-Za-z][A-Za-z-]+',b)))"
   ```

   得 `actual_cn_chars`（汉字数）与 `actual_en_words`（英文词）。
   中文稿判级取 `actual_cn_chars`；英文稿取 `actual_en_words`；双语稿（含英文摘要）以主体语言为准。
2. 从 HUD `draft.word_count_target` 取该类型目标区间 `[lo, hi]`（中英分别取）。
3. 落在区间内 → ✅ 通过；偏离则按红区判级：

| 偏离情况 | 严重程度 | 修订方向 |
|----------|---------|---------|
| 实际 < 类型偏短红区（如 T1 < 3k 词 / < 0.6万字） | 一般→严重 | 补核心分支 / 代表工作 / 批判深度，勿为凑数堆砌 |
| 实际 > 类型偏长红区（如 T1 > 12k 词 / > 2.5万字且非 T5） | 一般 | 压缩流水账、合并重复叙述、强化批判聚焦 |
| T4 只有图、无方法说明（数据来源不可追溯） | 严重 | 补数据与方法小节（不靠加字数，靠补透明性） |
| 声称 T2 / T3 但无 PRISMA 且 < 类型下限 | 严重 | 补方法学，或降级声明为 T1（措辞同步） |

4. 字数结论写入审核报告，作为"是否达到提交标准"的依据之一：
   - 偏离红区且未修 → "达到提交标准"判 **否**（一般/严重问题未闭环）。
   - 落在区间或用户知情接受偏差 → 通过。

> 注：微型 / 快速综述（不论类型）单独按 1.5k–3k 词 / 3k–6k 字 评估，不套用上表上限。

## 五、修订建议

对每处问题给出：
- **位置**：章节/段落
- **问题**：具体描述
- **严重程度**：严重/一般/建议

## 五-B、P8 八维度预自评（他审前的自我体检）

> 按 `stages/08-publication-review.md` §四-B 的 8 维度评分表，**以审稿人立场**
> 对终稿做一轮快速预打分（目标：提前暴露 ≤3 分维度，别把低分项留到 P8 才发现）：

1. 逐维度按锚点打分，**重点核对默认 20 分权重的 D4（综合深度）**——流水账是
   综述最高频死因，自审时最容易高估自己；
2. 对照一票否决项自检（编造文献 / 类型-方法不自洽 / 缺口无据 / T5 反方缺失）；
3. 预估总分与最弱的 2 个维度写入审核报告（"预估 P8 评分"行）；
4. 最弱维度能在 P7 内修的（如补图表解读、压流水账段落）先修再进 P8；
   需要回到 P4/P5 的（如缺综合框架）如实标注，不掩盖。

## 六、Hard Stop

> 强约束：若 P6 参考文献真实性核验 `gate_passed = false`（仍有 ❌ UNVERIFIED
> 且用户未确认"以人工核对为准"），则"是否达到提交标准"强制为 **否**，
> 不得整体通过。

展示审核报告和修订建议。用户选择：
- **逐条修改**：逐条处理问题
- **整体通过**：确认综述达到提交标准（含字数闸门通过）→ 进入 **P8 审稿人角色发表级审查**
- **回到 P5**：大幅修改综述结构
