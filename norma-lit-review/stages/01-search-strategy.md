# P1 · 检索策略制定

> Norma理工科文献综述 · Stage 01
> 目标：将用户的研究主题转化为可执行的检索策略

---

## 一、主题解构（三要素拆解）

读取用户的主题描述，拆解为：

| 要素 | 说明 | 示例（"基于视觉的嵌入式实验教学平台"） |
|------|------|------|
| **核心概念** | 1-2 个核心学术概念 | 嵌入式系统、实验教学 |
| **技术/方法** | 涉及的具体技术方法 | 计算机视觉、边缘计算 |
| **应用场景** | 研究成果落地的场景 | 工科实验教学、虚拟仿真 |

### 理工科特殊考量

- **是否有硬件依赖？** → 检索时加 hardware/implementation 关键词
- **偏理论还是偏工程？** → 影响数据库选择（理论偏 arXiv，工程偏 IEEE）
- **涉及交叉学科？** → 需要拆出交叉关键词（如"嵌入式+教育"= "engineering education" + "embedded systems"）

## 二、关键词扩展（中英文双向）

> **方法论要求**：先按 `modules/search-methodology.md` §一 构建**概念组块**（concept blocks），
> 再做关键词扩展——每个概念组块是同义词集合（OR），块间 AND。检索式必须是可以
> 原样复制回数据库重跑的完整文本（可复现留痕的基础）。

### 2.1 中文关键词组配

```
核心概念 AND 技术方法
核心概念 AND 应用场景
技术方法 AND 应用场景
(核心概念 OR 同义词) AND (技术方法 OR 同义词)
```

对每组关键词同步生成知网专业检索式（`SU=...`）、万方检索式。

### 2.2 英文关键词组配

```
"core concept" AND "technical method"
"core concept" AND "application scenario"
```

对每组生成 Semantic Scholar / arXiv / IEEE Xplore 检索式。

### 2.3 同义词/近义词映射表

为每个关键词列出中英文同义词、缩写、上位词/下位词：

```
嵌入式系统 → embedded system, microcontroller, SoC, FPGA, edge device
计算机视觉 → computer vision, machine vision, image processing, visual recognition
实验教学 → experimental teaching, lab instruction, hands-on learning, practical training
```

## 三、数据库选择策略

| 场景 | 推荐数据库 | 原因 |
|------|-----------|------|
| 中文核心期刊投稿 | 知网(CNKI)+万方 | 中文学术文献全覆盖 |
| 英文会议/期刊 | IEEE Xplore + Semantic Scholar | 工程类文献权威来源 |
| **正式刊出（无订阅/可脚本化）** | **OpenAlex** | 4.5 亿条正式刊出文献，免 key，可直接取被引数等结构化字段 |
| 前沿/预印本 | arXiv (cs.* / eess.*) | 最新研究，无付费墙 |
| 学位论文参考 | 知网博硕 + ProQuest | 博硕论文方法章节详细 |
| 专利/工程方案 | 中国专利局 + Google Patents | 工程实现细节 |

根据用户的目标场景选定 2-4 个数据库。详见 `modules/stem-databases.md`。

## 三-B、按 review_type 分支的检索要求

读取 HUD `review_type`，检索深度与严谨度按类型区分（详细要素见 `modules/review-types.md`）：

- **T1 / T5**：检索服务于"充分覆盖代表工作"，允许代表性抽样，不必穷举；时间窗可宽松。
- **T2 / T3**：检索必须**可复现**——在 P1 产出明确检索式（含布尔逻辑、字段限定）、完整数据库清单 + 时间窗；T2 还需预留预注册空间（检索式锁死、不可中途增删）。
- **T4**：数据库须为**结构化引文源**（优先 WoS / Scopus 批量导出）。**无订阅时不再直接降级**——
  改用免 key 的结构化替代源：
  - **OpenAlex**（`fetch_lit.py search`）：4.5 亿条正式刊出文献，直接输出 `cited_by_count`、
    期刊、年份、主题等结构化字段，可替代 WoS/Scopus 做被引与分布统计；
  - **OpenCitations**（`fetch_lit.py citing`）：DOI→DOI 引文关系（CC0），
    支撑共引 / 参考文献网络分析。
  - ⚠️ 边界：OpenCitations 对**高被引 DOI 常超时**（服务端限制），且**空数组 ≠ 零被引**；
    此时用 `fetch_lit.py enrich` 取 OpenAlex 的 `cited_by_count` 兜底。
  仅当这些结构化源**均不可用**（如网络受限）时，才降级为 T1 并用 P4 轻量计量，不得假装计量。
  详见 `modules/verified-retrieval-protocol.md` §二.5。

> 此分支仅约束检索的"严谨度与范围"，不影响关键词扩展（第二节）的通用流程。

## 四、种子文献登记（召回率测试的基准）

向用户收集并登记 5–10 篇"这个领域绕不开的文献"（用户已有积累 / 公认经典 / 导师同行推荐），
写入种子文献表：

| 种子文献 | 来源 | 预期命中的库 | 用途 |
|---------|------|-------------|------|
| {标题/DOI} | 用户提供 | 知网+S2 | P2 召回率测试基准 |

> 这批种子是 P2 **召回率测试**（search-methodology §三）的基准：检索式定稿后若召回不了
> 已知经典，说明检索式有"洞"，必须补检。没有种子文献时，先用块A核心词做一次试检，
> 取高被引 Top 5 作为临时种子。

## 五、纳入/排除标准

与用户确认后写入：

### 纳入标准（默认）
- 发表时间在指定范围内
- 与核心概念直接相关（标题/摘要匹配关键词）
- 同行评审来源（期刊/会议论文，排除预印本中未审稿的）

### 排除标准（默认）
- 非学术来源（博客、新闻、科普文章）
- 摘要缺失或无法获取全文
- 明显不相关学科（如"嵌入式"匹配到"嵌入式金融"）

### Hard Stop
**输出检索策略草案**（关键词表 + 检索式 + 数据库列表 + 纳排标准），
等待用户确认后进入 P2。

## 七、理工科检索反模式

- ❌ 只用中文关键词搜中文库 → 忽略英文文献（工程领域大量高质量文献是英文）
- ❌ 关键词太泛（如"人工智能 教育"→ 上万结果无法筛选）
- ❌ 关键词太窄（如"基于YOLOv8的STM32实验教学"→ 零结果）
- ❌ 不区分"嵌入式系统"与"嵌入式金融"（学科过滤缺失）
