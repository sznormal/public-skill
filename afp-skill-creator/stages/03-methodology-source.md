# P3 · 方法论来源确认（领域自适应）

> AFP Skill Creator · Stage 03
> 目的：确认 skill 背后的方法论从哪来、是否真实、是否完整到能支撑步进式流程——AFP 的核心是"专家方法论 agent 化"，方法论不清，后面全是空转

---

## 一、为什么方法论来源是独立阶段

一个 AFP skill 的价值 = **方法论价值 × agent 化质量**。

P1 确认了"要做什么"，P2 确认了"是什么类型"，但都没有回答最关键的问题：**这个 skill 凭什么能把活干到 90 分？** 答案只能是方法论。没有方法论支撑的 skill 只是"提示词壳子"——用户用一次就会发现它给不出稳定的高质量产出。

本阶段结合用户在 P1 识别的领域，Read `modules/domains/{domain}.md` 获取该领域的方法论参考，然后完成三件事：

1. 确认方法论**来源类型**（§二）
2. 把方法论**显性化**成可执行流程（§三）
3. 检查方法论**完整性**——能否支撑步进式 skill（§四）

---

## 二、方法论来源的四种类型

### 类型 1 · 个人原创方法论（AFP 最推崇）

你在长期实践中沉淀的独门方法——带过 50 个学生、做过 100 个项目后总结出的"成事路径"。

- **验证要求**：能举出至少 3 个用这套方法做成的真实案例
- **权属**：完全属于你，agent 化后进入你的命名空间
- **例**：一平的抗压缩协议 / 学君的四审剧场

### 类型 2 · 经典方法论移植

领域内公认的经典方法，你把它工程化成步进流程。

- **验证要求**：给出真实出处（书 / 论文 / 官方指南），符合 AFP-SPEC §6 Evidence Chain
- **权属**：方法论属于原作者，**你的贡献是 agent 化工程**——skill 文档中必须署明方法论来源
- **例**：Braun & Clarke 反思性主题分析 / SCQA 金字塔 / Strauss & Corbin 三级编码

### 类型 3 · 组织内部沉淀

团队 SOP、内部手册、培训教案的 agent 化。

- **验证要求**：确认你有权把它 agent 化（组织授权或本人是权属人）
- **权属**：注意与组织的约定；对外上架 AFP-ecosystem 前需确认无保密义务
- ⚠️ **禁止**：把他人未公开的方法论（如别人的内部课件、付费课程讲义）拿来 agent 化上架

### 类型 4 · 混合型（最常见）

经典框架打底 + 个人经验改造。

- **验证要求**：分层说明——哪层来自经典（给出处）、哪层是你的改造（给案例）
- **例**：青泥理论框架家族 = 经典研究范式分类 + 学术志辅导实践中提炼的 AFP 流程

## 三、方法论显性化五问

**专家方法论多数是隐性的**——"我看一眼就知道怎么改"没法 agent 化。用下面五问把隐性经验逼成显性流程：

### 问 1 · 输入是什么？

用户启动这个流程时，必须提供什么材料？（例：3-5 篇核心文献 / 一份访谈记录 / 一个研究问题）

### 问 2 · 步骤是什么？

从输入到输出，你自己做的时候分几步？每步的动作是什么？**能排出顺序的才是流程，排不出顺序的还是直觉。**

### 问 3 · 每步的判断标准是什么？

你怎么知道这一步做对了、可以进入下一步？（例："主题矩阵至少覆盖 3 个维度且互斥"）**判断标准就是未来 skill 里的 Hard Stop 检查项。**

### 问 4 · 常见失败点在哪里？

新手做这件事最容易在哪几步栽跟头？**失败点就是未来 skill 里的反模式清单。**

### 问 5 · 输出长什么样？

理想产出的结构是什么？有没有一份"90 分样例"？**输出结构就是未来 skill 的 Output Structure schema（AFP-SPEC §7）。**

**同时收集独家语料**：有 90 分样例就请用户当场交出来——范文、成功案例、话术库、评审意见、被打回的反面样例都算。经验决定流程，语料决定手感，两者是不同的护城河：流程写进 stages/，语料在 P4 挂载（`modules/exemplars.md` 或 `templates/`），P6 写作时作为 few-shot 参照。⚠️ 语料含客户 / 学生 / 患者等真实信息时，收集前先脱敏。

五问答完，方法论就从"我的经验"变成了"可执行、可检查、可交接的流程"——这正是 P6 内容撰写的原材料。

## 四、方法论完整性检查（步进式支撑力测试）

对照五问答案，检查方法论能否支撑一个步进式 AFP skill：

| 检查项 | 通过标准 | 对应 AFP 机制 |
|---|---|---|
| 阶段可枚举 | 步骤能排成 P1 → P2 → … 的有序序列 | 阶段路由表 |
| 每阶段有判断标准 | 每步都答得出"怎么算完成" | Hard Stop 检查项 |
| 关键决策点可识别 | 能指出哪几步必须用户拍板（选方案 / 定方向） | Hard Stop + 多方案选择 |
| 失败点可枚举 | 至少列出 5 个常见错误 | 反模式清单 |
| 输出有结构 | 说得出产出的字段 / 章节 / 格式 | Output Structure schema |
| 事实可溯源 | 流程中的事实性主张有来源 | Evidence Chain |

**判定**：
- 6 项全过 → 方法论完整，进入 P4 结构设计
- 缺 1-2 项 → 当场补齐（本 skill 引导用户逐项补）
- 缺 3 项以上 → 方法论还不成熟，建议先回到实践中沉淀，或降级为 Bronze 探索期 skill

## 五、领域自适应对照

Read `modules/domains/{domain}.md` 后，做两个对照：

1. **方法论参考对照**：你的方法论与该领域的经典方法论谱系是什么关系？（移植 / 改造 / 原创补位）——帮助在 P5 的 description 里准确定位
2. **领域反模式对照**：你的方法论是否内置了对该领域专属反模式的防御？（例：学术领域的 A9 引用虚构 → 你的流程里有没有引用验证步骤？）

领域模块缺失时（用户领域不在预置清单内），Read `modules/domains/generic.md` 走自定义领域引导。

## 七、反模式警告

方法论来源阶段常见错误：

- ❌ **方法论虚构**：给不出出处也给不出案例，纯靠"我觉得应该这样"——做出来的是提示词壳子
- ❌ **出处幻觉**：引用的经典方法论书目 / 论文不存在或张冠李戴——违反 Evidence Chain，上架会被 Committee 打回
- ❌ **隐性经验直接 agent 化**："让 AI 学我的感觉"——五问答不出来就还不能进 P4
- ❌ **步骤即目录**：把"第一步做 X"写成"第一章是 X"——流程要有动作和判断标准，不是产出物目录
- ❌ **窃取他人方法论**：把别人的付费课程 / 未公开讲义 agent 化——违反 AFP 行动派治理规则，撤销命名空间授权级别的违规
- ❌ **完美主义卡死**：方法论 6 项检查过了还在无限打磨——先做 Bronze 版跑起来，迭代靠 P9
