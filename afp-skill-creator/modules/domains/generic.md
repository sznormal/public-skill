# 通用领域模块（未预置领域兜底）

> AFP Skill Creator · Domain Module
> 领域：用户所在领域不在 10 个预置领域清单内时的兜底
> 适用：任何结构化内容生产领域——HR、财税、建筑、游戏策划、心理咨询、非遗传承……
>
> 本模块在 P1 用户选择"其他领域"后被 Read on demand。它不提供现成领域知识，而是**引导用户在 30 分钟内建出自己领域的迷你领域档案**，供 P3-P6 使用

---

## 一、先判断：真的没有预置模块吗？

先做一次归并检查——很多"其他领域"其实是预置领域的子域：

| 用户说的领域 | 实际可用模块 |
|---|---|
| 智库 / 行研 / 白皮书 | policy.md 或 investment-research.md |
| 企业内训 / 知识付费课程 | education.md |
| 公文 / 申报书 | policy.md（政府文书部分） |
| 自媒体 / 公众号深度文 | journalism.md 或 creative-writing.md |
| 用户研究 / 竞品分析 | product.md |

能归并 → Read 对应模块，退出本模块。真归并不了 → 继续 §二。

---

## 二、领域档案五步引导

逐步提问，每步产出一段档案。全部完成后写入 `{project_path}/domain-profile-{领域名}.md`，作为该用户的"私有 domain 模块"。

### Step 1 · 领域概述三问

1. 这个领域的**典型内容产出物**是什么？（列 3-6 种，如"尽调报告 / 评估意见书 / 整改方案"）
2. **谁生产、谁消费**这些产出物？（角色画像）
3. 产出物的**质量高低由谁、按什么标准评判**？（评审人 + 评判标准——这直接决定 skill 的 90 分定义）

### Step 2 · AFP 三支柱具象化（填表）

| AFP 支柱 | 引导问题 | 用户答案 |
|---|---|---|
| **Auto · 自主决策** | 流程中哪些环节 agent 可自主推进？哪些必须人拍板？ | {…} |
| **Flow · 协同流动** | 从原料到成品经过哪几站？站与站之间传递什么？ | {…} |
| **Prompt · 提示词工程** | 这个领域的行文有什么范式？（结构 / 语态 / 禁忌） | {…} |

### Step 3 · 领域方法论谱系

引导用户列出该领域的 2-4 个公认经典方法论 / 标准 / SOP（含出处——真实性按 AFP-SPEC §6 验证），并标注：用户自己的方法论与它们是移植、改造还是补位关系。**列不出任何公认方法论时要警惕**：这个领域可能还不适合做结构化 skill，或用户对领域的了解还不够深。

### Step 4 · 领域反模式清单（至少 5 条）

引导句式："在你的领域里，**新手最常犯、且评审一眼就能看出来**的错误有哪些？"每条按 academic.md 的格式整理：

```
### ❌ G{N}. {反模式名}
{一句话描述}
**症状**：{可观察的具体表现}
**修正**：skill 应 {防御动作}
```

凑不满 5 条时，用通用四问补：事实层错误（数据/引用）？逻辑层错误（论证/推断）？结构层错误（组织/详略）？合规层错误（伦理/法律/保密）？

### Step 5 · 触发词 + 证据链标准

- **触发词四类框架**：对象词（产出物名）× 阶段词（流程站名）× 场景词（细分情境）× 服务词（帮我写/改/审）——组合出 10-15 个
- **证据链标准**：该领域的事实性主张靠什么来源背书？（法规条文号 / 行业标准编号 / 财报页码 / 访谈记录……）逐类定最低标准，达不到标 `unverified`

## 三、档案产出格式

```markdown
# {领域名} · 领域档案（domain-profile）

> 由 afp-skill-creator generic 模块引导生成 · {date} · 作者：{partner}

## 一、领域概述          ← Step 1
## 二、AFP 三支柱具象化   ← Step 2
## 三、方法论谱系         ← Step 3
## 四、领域反模式（G1-G{N}）← Step 4
## 五、典型触发词         ← Step 5
## 六、证据链标准         ← Step 5
## 七、合规目标建议（Bronze/Silver/Gold 适用场景）
```

后续 P3-P6 凡是写"对照 `modules/domains/{domain}.md`"处，一律改为对照这份档案。

---

## 四、档案 → 正式 domain 模块的贡献通道

你的领域档案如果满足以下条件，可提议升格为 AFP Skill Creator 的正式 domain 模块（造福后来的同领域合伙人）：

1. 基于该档案做出的 skill 已达 Silver（3 个真实用户案例）
2. 反模式清单扩充到 10 条以上
3. 方法论谱系出处全部可验证

流程：提交 Steering Committee 审议 → 通过后档案整理为 `modules/domains/{领域名}.md` 并入本 skill → 贡献者终身署名。**这也是一种共同体贡献，计入积分。**

## 五、反模式警告（使用本模块时）

- ❌ **跳过归并检查**：明明是 education 子域却从零建档案——重复劳动且质量低于预置模块
- ❌ **档案一步到位幻想**：想把领域百科全书写进档案——档案只服务于当前要做的 skill，够用即可，迭代靠运行期
- ❌ **反模式清单写成愿望清单**："内容要有深度"不是反模式——反模式必须有可观察的症状和可执行的防御
- ❌ **方法论谱系空转**：列不出任何公认方法论还硬做——先回领域里泡半年
- ❌ **档案私藏**：档案成熟了不走贡献通道——违背 AFP 行动派共同体精神，也亏了署名和积分
