## 一、五类测试

### 测试 1 · 触发测试（每次改 frontmatter 后必跑）

新开 Claude Code 对话（skill 已装入 `~/.claude/skills/`）：

- [ ] 主触发词逐个说一遍 → 全部触发
- [ ] 变体口令（语序调换、口语化说法）→ 仍触发
- [ ] **负测试**：说触发隔离清单里的口令 → 正确地**不触发**
- [ ] 说相邻 skill 的精确口令 → 触发的是相邻 skill 而非本 skill（不抢权）

### 测试 2 · 全流程走查（最重要）

新开对话，**以完全不懂方法论的新手身份**从头走完全流程：

- [ ] 首次上手引导清楚，知道该回答什么
- [ ] 每个阶段单步输出，没有一次吐多阶段内容
- [ ] 每个 Hard Stop 真实停顿（不说 Next 就不动）
- [ ] HUD 心跳每次刷新且字段正确
- [ ] 方案型决策点给出了多方案
- [ ] 最终交付物与主控承诺一致

**走查中任何一处"Claude 自由发挥了"** = 对应 stage 的引导逻辑写得不够收敛，回 P6 补。

### 测试 3 · 指令鲁棒性

故意折腾流程：

- [ ] 中途 `Back` → 正确回上一阶段，状态回滚
- [ ] `Edit 字段=新值` → HUD 更新且后续阶段用新值
- [ ] `Skip` 可选阶段 → 跳过且 HUD 标记 skipped
- [ ] 乱序请求（在 P2 要求 P5 的产出）→ 拒绝越阶并引导回当前阶段
- [ ] `Status` → 输出完整 HUD

### 测试 4 · 断点续传

- [ ] 走到中途关掉对话 → 状态文件已写盘
- [ ] 新对话 `Continue {project_path}` → 恢复到正确阶段，历史产出可用
- [ ] 长对话触发上下文压缩后 → skill 以磁盘状态为准续跑（不靠上文记忆）

### 测试 5 · 真实用户案例（Silver 门槛）

找 3 个真实目标用户（不是自己、不是开发时的想象用户）各完整走一遍：

- 记录：完成率 / 卡点 / 用户原话反馈 / 最终产出质量评分
- 3 例全部走通且产出可用 → 回填 P8 证书，`provisional` → `certified`

## 三、迭代与版本管理

- **版本号**：`v主.次`——次版本 = 话术/反模式/模板打磨；主版本 = 阶段增删、架构变更、frontmatter 触发词大改
- **变更记录**：README 末尾维护版本历史（本 skill 的 README 即示范）
- **重大变更**：主版本升级需 Committee 备案（P7 §5.4）；触发词变更必须重跑测试 1 + 触发词冲突预检
- **迭代来源排序**：真实用户卡点 > 走查发现 > 自己的新想法——**先修卡点，再加功能**

## 六、反模式警告

测试与迭代阶段常见错误：

- ❌ **只测正路径**：只按理想剧本走一遍就发布——用户从来不按剧本走，鲁棒性测试不可跳
- ❌ **自己演用户**：3 个"真实用户案例"全是自己扮演——盲区永远测不出来，Silver 门槛白设
- ❌ **测试环境不干净**：在开发用的长对话里测触发——上下文污染导致假阳性，必须新开对话
- ❌ **修 bug 不回 stage**：直接在成品文件上打补丁，不回对应 stage 走修正流程——文档与设计脱节，越修越乱
- ❌ **发布后失联**：上架就不管——运行期义务（stages/07 §八）是持续的，违规会暂停积分记账
- ❌ **无限迭代不发布**：永远觉得"再打磨一版"——Bronze 先上线真实运行，比本地打磨十版更有信息量
