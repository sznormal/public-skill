# 职业本科智慧课程框架建设方法论

## 技能概述

本技能凝练了职业本科智慧课程建设的完整方法论，涵盖从政策依据分析到教材编写的六阶段流程。适用于任何职业本科专业课程，用户输入课程名称后即可按照此方法论系统化地构建课程框架。

## 触发条件

- 用户要求新建职业本科课程框架
- 用户要求重构或优化现有课程体系
- 用户要求设计项目化课程结构
- 用户要求编写教材目录或教材内容
- 用户提到"智慧课程""课程框架""课程建设""项目化课程"等关键词

## 六阶段建设流程

### 阶段一：政策依据分析

分析职业教育相关政策文件，提取课程建设的脉络框架。核心政策依据：

1. **教育强国建设规划纲要** — 数字化转型方向
2. **新双高计划** — 五金建设（金专业、金课程、金教材、金师资、金基地）+ 六维度评价
3. **职教司一号文件** — 能力图谱结构（项目→任务→工作步骤→技能点/知识点/素养点）

提取出的通用建设脉络框架包含五个维度：能力图谱、五金建设、岗课赛证融通、三主编制度、数字化资源。

> 详细政策要点和框架结构见 `references/policy_framework.md`

### 阶段二：证赛标准调研

搜索与课程相关的职业技能证书标准和技能竞赛标准，提取知识点和技能点清单。

核心步骤：
1. 搜索职业技能证书标准（排除1+X，聚焦行业协会/学会认证）
2. 搜索技能竞赛标准（世界技能大赛、全国职业院校技能大赛、行业赛）
3. 按排除规则裁剪（去除与课程定位不符的方向）
4. 提取知识点和技能点清单，形成"证赛标准对照表"

> 详细调研方法和排除规则见 `references/cert_competition_research.md`

### 阶段三：产业调研

立足目标区域（如珠三角、长三角等），调研相关产业的头部企业，确定"三主编"行业合作伙伴。

核心步骤：
1. 调研目标区域相关产业链的头部企业（3-5家）
2. 分析企业核心产品与课程的相关度
3. 确定校企合作方向（实训基地、教材编写、师资互聘）
4. 形成"三主编"名单：企业技术专家 + 学校专业带头人 + 行业权威专家

> 详细调研方法和三主编制度见 `references/industry_research.md`

### 阶段四：课程框架搭建

基于前三阶段成果，设计课程框架。

核心设计原则：
1. **项目化结构**：课程由若干"项目"组成，每个项目对应一个岗位场景
2. **岗位场景命名**：项目以岗位角色命名（如"XX工程师入职上手"），不以技术功能命名
3. **能力图谱递进**：项目→任务→工作步骤→技能点/知识点/素养点
4. **课时总量**：职业本科课程建议64学时（理论约30%+实验约70%）
5. **角色分离**：不同项目聚焦不同岗位角色，避免内容重叠
6. **虚拟仿真融入**：引入QEMU等虚拟仿真工具，实现"先虚拟后实物"开发范式
7. **AI工具融入**：在适当项目中融入AI开发工具，落地"人机协同设计"

> 详细设计原则和决策规则见 `references/course_design_principles.md`

### 阶段五：迭代优化

课程框架搭建后，按以下维度进行迭代优化：

1. **课时压缩**：合并关联任务，减少理论学时比例
2. **内容裁剪**：删除与其他课程重叠的内容，聚焦核心方向
3. **角色分离**：确保每个项目聚焦一个明确的岗位角色
4. **验收标准体系**：使用功能验证+质量规范+交付物标准，不使用时间标准
5. **shellcheck等质量工具**：引入行业标准工具作为质量规范检查
6. **实验项目对照**：将课程实验与框架中的项目/任务建立对照表，确保实验全覆盖，标记未纳入实验及原因

### 阶段六：教材编写

按三层目录结构编写教材：

```
课程名称/
├── 项目一_岗位场景名称/
│   ├── 00_项目总览/
│   │   ├── 01_项目概述与工作场景.md
│   │   ├── 02_学习目标与验收标准体系.md
│   │   ├── 03_交付物目录树.md
│   │   └── 04_岗课赛证对接表.md
│   ├── 任务1_任务名称/
│   │   ├── 01_情景导入.md
│   │   ├── 02_知识准备.md
│   │   ├── 03_技能点.md
│   │   ├── 04_思政点.md
│   │   ├── 05_实战演练.md
│   │   ├── 06_避坑指南.md
│   │   ├── 07_验收评价.md
│   │   ├── 08_任务评价单.md
│   │   └── 09_理论测试题.md
│   ├── 任务2_任务名称/  (同上9个模块)
│   ├── 任务3_任务名称/  (同上9个模块)
│   └── 99_项目综合验收/
│       ├── 01_综合实战项目.md
│       └── 02_岗课赛证对照表.md
├── 项目二_.../
└── ...
```

每个内容模块的写作规范：
- **知识准备**：从基础概念到操作命令，逐参数详解，减少知识跳跃。必须包含通用格式讲解（如命令格式、语法结构），每个命令/语法必须有选项详解表和输出解读。
- **技能点**：每个技能点含操作要求和验收标准（功能验证/质量规范/交付物标准，不使用时间标准）
- **思政点**：每个任务3-4个思政融入点，含教学引导和价值映射
- **情景导入**：以职业场景（邮件/任务指令/现场情境）导入，含任务分解
- **避坑指南**：常见问题+原因分析+解决方案三段式
- **验收评价**：6维度100分（技能40%+知识20%+素养20%+价值10%+团队10%）
- **任务评价单**：三方评价（自评20%+互评30%+行业专家50%），四级评分细则（满分/良好/合格/不合格），每个技能点逐条评价
- **理论测试题**：10单选(30分)+5填空(20分)+5简答/改错/思政(50分)=100分，基于知识准备内容出题，含参考答案与解析

> 详细教材结构和写作规范见 `references/textbook_structure_template.md`
> 理论测试题出题规范见 `references/theory_test_specification.md`
> 任务评价单规范见 `references/task_evaluation_specification.md`

## 使用方式

当用户输入课程名称后，按以下步骤执行：

1. **确认课程信息**：课程名称、专业方向、目标学时、目标区域、是否有已有资源
2. **按六阶段流程推进**：每阶段完成后与用户确认，再进入下一阶段
3. **输出成果物**：
   - 阶段一-三：政策分析报告、证赛标准清单、产业调研报告
   - 阶段四：课程框架文档（含项目/任务/学时/验收标准）
   - 阶段五：优化版课程框架
   - 阶段六：三层目录结构教材文件

## 关键设计约束

- **不使用时间标准**：验收标准使用功能验证+质量规范+交付物标准，因网络/硬件差异导致时间不可控
- **岗位场景命名**：项目以岗位角色命名，不以技术功能命名
- **虚拟仿真优先**：先虚拟后实物开发范式
- **不直接使用企业名称**：教材中使用"某企业"替代真实企业名
- **浅色背景深色字体**：所有可视化图表使用浅色背景+深色字体
- **知识准备零跳跃**：每个概念必须从基础讲起，每个命令必须逐参数解释
