# 四维审查详细评分细则

本文件为 `textbook-review` 技能提供四维审查的逐项判据。每维按 **红（0 分，阻断性缺陷）/ 黄（0.5 分，需优化）/ 绿（1 分，达标）** 三档评分，加权求和得 0–100 分。

权重：小白可执行性 25%｜技术严谨性 35%｜教学法有效性 20%｜出版规范性 20%。

---

## 维度一：小白可执行性（25%）

| 审查项 | 红（阻断） | 黄（待优化） | 绿（达标） |
|--------|-----------|-------------|-----------|
| 起点明确 | 无环境准备 / 原料清单，读者不知从哪开始 | 有清单但缺版本或路径 | 明确给出环境、版本、目录、原料 |
| 命令上下文完整 | 命令脱离上下文（不知在哪执行、前置是什么） | 大部分有上下文，个别缺失 | 每条命令标明目录、依赖、预期结果 |
| 无认知断层 | 出现"以此类推""显然""读者自证"等不可执行跳跃 | 个别步骤省略但可推断 | 每步闭环，零基础可独立完成 |
| 术语解释 | 关键术语未定义直接使用 | 部分术语在文末统一解释 | 首次出现即解释或给类比 |
| 排障指引 | 典型报错无任何应对 | 仅提示"查日志" | 列出常见报错与对应解法 |

**常见反例**：`cd 到项目目录后运行 make`（未说明项目目录从何而来）；`pip install xxx`（未说明 Python 版本与虚拟环境）；`参考上一节配置网络`（上一节并未出现）。

---

## 维度二：技术严谨性（35%，一票否决维）

| 审查项 | 红（阻断） | 黄（待优化） | 绿（达标） |
|--------|-----------|-------------|-----------|
| 概念准确 | 定义错误 / 概念混淆 | 表述不严谨但结论正确 | 定义精确、无歧义 |
| 代码可运行 | 代码有语法 / 逻辑错误，无法运行 | 可运行但风格或健壮性欠佳 | 可运行、与正文一致、无复制错误 |
| 公式 / 参数 | 公式或单位错误 | 推导跳步但结果正确 | 公式、参数、单位均正确 |
| 数据有源 | 数据 / 版本号无来源或疑似编造 | 有来源但年份滞后 | 标注来源与日期，可核查 |
| 引用合规 | 事实性引用错误 | 引用格式不统一 | 引用准确、格式规范 |

**一票否决规则**：任何"红"项（事实错误、代码不可运行、公式错误）必须清零，否则整体判定为"重大返工"，无论其他维度得分多高。

**常见反例**：把 `sudo` 与 `root` 混用导致权限说明错误；示例代码使用与正文不同的库版本；把 GPIO 引脚号说错；引用不存在的论文结论。

## 维度三：教学法有效性（20%）

| 审查项 | 红（阻断） | 黄（待优化） | 绿（达标） |
|--------|-----------|-------------|-----------|
| 递进合理 | 难度断层，后面陡然超前 | 个别小节节奏偏快 | 由浅入深，无跳跃 |
| 章节闭环 | 只讲操作不讲为什么 | 部分有目标说明 | 每节含"为什么 / 学什么 / 怎么用" |
| 示例匹配 | 示例与学习目标无关 | 示例偏难或偏易 | 示例精准匹配目标 |
| 类比到位 | 抽象概念无解释 | 有类比但不够贴切 | 抽象概念有具象类比（小学生能懂） |
| 检查点 | 全章无小结无练习 | 仅有小结 | 含小结 + 检查点 / 练习 |

**常见反例**：直接抛出寄存器地址表而不解释寄存器的作用；先讲复杂 API 再补基础；一章 40 页无一处小结。

---

## 维度四：出版规范性（20%）

| 审查项 | 红（阻断） | 黄（待优化） | 绿（达标） |
|--------|-----------|-------------|-----------|
| 标题层级 | 层级跳跃（H1 直接到 H3） | 个别层级不统一 | 连续递进，无跳跃 |
| 图表规范 | 图无编号 / 无标题 / 正文未引用 | 编号或标题缺失其一 | 图有编号、标题、正文引用 |
| 代码块 | 大量代码块无语言标识 | 个别缺失 | 全部标注语言 |
| 占位残留 | 含 TODO / FIXME / 待补充 | 少量草稿标记 | 无残留占位 |
| 术语统一 | 同一概念多种译法混用 | 个别不统一 | 全文术语 / 单位 / 标点统一 |
| 版权合规 | 引用图片 / 代码未授权 | 授权说明不全 | 引用与版权标注合规 |

**自动化辅助**：`scripts/review_check.py` 可自动检出标题层级跳跃、占位残留、代码块无语言、空链接、图片缺失、表格分隔符异常。人工精读负责脚本无法判断的语义类问题（术语统一、版权、类比质量）。

---

## 评分计算示例

假设四维得分分别为：小白 0.8、严谨 0.9、教学 0.7、规范 1.0

总分 = 0.8×25 + 0.9×35 + 0.7×20 + 1.0×20 = 20 + 31.5 + 14 + 20 = **85.5**

若技术严谨性含"红"项 → 即便 85.5 也判"重大返工"。本例严谨性 0.9 且无红 → **建议放行**。
