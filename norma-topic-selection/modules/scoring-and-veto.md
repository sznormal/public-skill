# 模块 · 评分卡与否决规则

> P5 调用。**分数的作用是暴露薄弱环节、组织师生讨论，不替代导师判断。**

## 一、8 维权重与判据

| 维度 | 权重 | 0–100 打分锚点 |
|---|---:|---|
| **空白真实性** | 20% | 六重门 A–C 全过 = 80+；A 门单库 = 50；发现同题预印本 = ≤30 |
| **重要性** | 15% | 能点名 3 个会引用它的团队/场景 = 80+；能说清后果但无人使用 = 50；"研究较少" = ≤40 |
| **新颖性** | 15% | 与最近 3 篇差异能一句话讲清 = 80+；差异只在数据集 = 50；与最近邻实质相同 = ≤30 |
| **机理深度** | 10% | 有理论界/闭式解 = 90；因果清晰 + 充分消融 = 75；只有相关性 = 50；说不清 = ≤30 |
| **可行性** | 15% | 四项全有 = 85；缺一项 = 60；缺两项 = 35 |
| **可验证性** | 10% | 公认基线 + 公开数据 + 客观指标 + 消融 = 85；基线需自建 = 55 |
| **期刊匹配与撞题** | 10% | 近 3 年持续发同主题 + 无撞题 = 85；持续发但有同题 = 45；不持续发 = 30 |
| **退路设计** | 5% | 证伪后仍有可发表副产物 = 80；转向分析型 = 60；无退路 = ≤40 |

## 二、否决规则（不可跳过）

```
规则 1：任一维度 < 50  →  整体否决（不看加权总分）
规则 2：空白真实性 < 70  →  直接否决
规则 3：师生双人打分单项分歧 > 20  →  该维度必须重议
```

**为什么需要规则 1**：加权平均会掩盖致命项。真实性 40 分、其他 6 维全 90，总分仍能过 70 线——然后你死在一篇三个月前上传的预印本上。

**为什么需要规则 3**：单人自评是自欺工具。两人独立打分、分歧 >20 的维度要么说明标准理解不一致（要重新定义），要么说明判断严重不同（要重议）。这比任何加权公式都更能防错。

## 三、参考线

| 加权总分 | 结论 |
|---|---|
| ≥80 | 优先推进（仍需过 MVP 止损） |
| 70–79 | 可开题（仍需过 MVP 止损） |
| <70 | 补料或换题（先看是哪个维度薄弱） |
| 触发任一否决 | 不论总分，**回 P3** |

⚠️ **分数是入场券，不是免死金牌**：高分题照样会在 P6 的 MVP 上死掉。低分题通过"补料"（补门 A/B 检索、补可行性）也可能救回来。

## 四、脚本用法

`scripts/score_topic.py` 接受如下 JSON：

```json
{
  "scores":       {"空白真实性": 75, "重要性": 60, "新颖性": 70, "机理深度": 55,
                   "可行性": 60, "可验证性": 80, "期刊匹配与撞题": 85, "退路设计": 60},
  "scores_advisor": {"空白真实性": 70, "重要性": 65, "新颖性": 55, "机理深度": 60,
                     "可行性": 60, "可验证性": 80, "期刊匹配与撞题": 85, "退路设计": 60},
  "weights": {"空白真实性": 20, "重要性": 15, "新颖性": 15, "机理深度": 10,
              "可行性": 15, "可验证性": 10, "期刊匹配与撞题": 10, "退路设计": 5}
}
```

- `scores_advisor` 可选（导师独立打分），提供后自动输出分歧清单；
- 退出码：`0` 通过 / `1` 触发否决 / `2` 输入不完整；
- 脚本**只做算术与规则判定，不给"该改哪个维度"的建议**——那需要人判断。

## 五、双人打分的正确用法

1. **先各自打分再看对方的**（避免锚定效应）；
2. 分歧 >20 的维度，当场讨论标准理解是否一致，而不是互相说服；
3. 讨论后**各自重新打分**并记录两个版本，保留差异轨迹；
4. 讨论纪要写进 `scorecard.md`，这是开题材料的一部分。

## 六、常见操弄（自查）

- ❌ 打完 45 分改成 55 分过线 → 等于关掉否决机制；
- ❌ 删掉低分维度不参与平均 → 权重必须写全并合计 100；
- ❌ 让学生一个人打分"代替师生双评" → 失去本机制意义；
- ❌ 拿分数当终点 → 真正的风险闸在 P6 的 MVP。
