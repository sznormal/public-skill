# P0 · 综述类型选择（Type Selection）

> Norma理工科文献综述 · Stage 00（前置硬门槛）
> 目标：在动手检索 / 撰写之前，确定本篇综述的**类型**。
>       不同类型决定检索方法学、分析维度、写作结构、质量门禁**完全不同**。
> 位置：必须最先执行（位于 P1 检索策略之前）。

---

## 一、为什么先选类型（给用户看的白话说明）

> 很多老师写综述时卡住，不是因为不会搜文献，而是**没想清楚"这篇综述是干嘛用的"**。
> 同样是"多智能体"这个课题，它可以是一份"给学生看的研究现状速览"，
> 也可以是一份"严谨证明某方法更优的系统证据"，还可以是一张"用数据画出的领域演进图"。
> 用途不同 → 写法天差地别。**所以动笔前，先定类型。**

---

## 二、五种综述类型（重点讲使用场景）

向用户展示下表。用户往往不懂术语，**重点讲"使用场景"，不要堆砌定义**。

### T1 叙述性 / 最新进展综述（Narrative / State-of-the-Art Survey）
- **使用场景**：想"讲清楚一个前沿方向现在做到哪了、有哪些代表工作、趋势和挑战"，
  不追求穷举全部论文、也不做统计合并。
  → 适合：论文的"相关工作"章节、赛事 / 项目方案、课题开题、快速建立领域认知。
- **特点**：按主题 / 应用域组织，带你的批判判断，提炼跨域模式。
- **不需要**：PRISMA 流程图、质量评估、预注册（最省力、最通用）。

### T2 系统综述（Systematic Review）
- **使用场景**：要严谨回答"某方法 / 技术是否更有效 / 更优"这类**具体证据问题**，
  结果要可复现、能被工程决策或政策引用。
  → 适合：学位论文核心章、方法对比类研究、需要 PRISMA 声明的期刊投稿。
- **特点**：有预注册协议、明确检索式 + 数据库 + 时间窗、纳入排除标准、
  PRISMA 2020 流程图、偏倚风险评估、证据综合。
- **代价**：最费时、要求最严（耗时可能是 T1 的 2–3 倍）。

### T3 范围综述（Scoping Review）
- **使用场景**：领域太新 / 太广，先"摸清全貌、定位空白、理清概念边界"，
  不追求对每篇做质量评价。
  → 适合：新兴交叉方向（如 LLM + 某工科）、基金申请前期、厘清术语。
- **特点**：检索范围广、产出"证据地图"（evidence map）、聚类与空白定位。
  遵循 PRISMA-ScR 报告清单。

### T4 文献计量综述（Bibliometric / Scientometric）
- **使用场景**：想**用数据说话**——引文网络、关键词共现、研究演进、
  国家 / 机构贡献、突现热点。
  → 适合：期刊要求"量化概览图"的 survey、趋势报告、学科发展评估。
- **特点**：依赖结构化数据源（WoS / Scopus / arXiv）、清洗规则、
  CiteSpace / VOSviewer 共现图、演进时间线、突现词检测。

### T5 批判性 / 观点综述（Critical / Perspective）
- **使用场景**：你**已有自己的理论框架或立场**，要"破旧立新"、提出假设或前瞻。
  → 适合：顶刊邀稿、提出新范式、方法论反思。
- **特点**：带作者明确立场，论证"为什么现有路线有局限 + 我的主张是什么"，
  不追求全面，追求洞察。

> 详细写作要素、必备产物、质量门禁见 `modules/review-types.md`。

## 三、结合用户选题给建议（关键！）

读取 HUD 的 `search.topic` 与 `search.time_range`，**自动推断推荐类型**并解释理由。
推断规则（命中即推荐；可多条命中，按表格顺序给主推）：

| 选题特征 | 推荐类型 | 理由 |
|----------|---------|------|
| 聚焦具体**应用域 / 技术路线**（如"多智能体在软件工程的应用"） | **T1** | 适合按域叙述 + 批判，无需穷举 |
| 含**"对比 / 优劣 / 是否更有效"**意图，或要支撑方法选型决策 | **T2** | 需可复现证据 + 偏倚评估 |
| 课题**新兴交叉**、范围模糊、想先摸清边界 | **T3** | 先 scoping 定位再深入 |
| 用户明确要**量化趋势图 / 引文网络 / 演进** | **T4** | 计量方法最契合 |
| 用户**已有理论框架 / 立场**，要提出新视角 | **T5** | 观点综述最合适 |

输出建议示例：
```
📌 结合你的选题「{topic}」，我建议选 **T1 叙述性 / 最新进展综述**：
   理由：你的选题聚焦具体应用领域，目标是快速建立领域认知 / 支撑相关工作章节，
   不需要穷举全部论文或做统计合并。T1 最省力且完全够用。
   如果你想强调"某类方法是否更优"，可改选 T2；想用数据画演进图，选 T4。

   📏 该类型字数目标（写作前请心里有数）：
      英文正文约 4k–8k 词 / 中文正文约 0.8万–1.5万字（不含摘要与参考文献）。
      偏短（<3k 词 / <0.6万字）易被审稿人疑"覆盖不足"；偏长（>12k 词）易被疑"流水账"。
      具体上限以你目标期刊作者指南为准。
```

> 若用户已在首屏说明目标期刊 / 场景，也要纳入推断（如目标为"医学类要求 PRISMA 的期刊"→ 推 T2/T3）。

## 四、Hard Stop（强制用户选择，绝不替用户决定）

展示类型表 + 你的推荐后，**必须等用户明确选择**才进入 P1。
提供快捷选项：

```
请选择本篇综述的类型（直接回复序号或类型名）：
  [1] T1 叙述性 / 最新进展综述      ← 推荐
  [2] T2 系统综述
  [3] T3 范围综述
  [4] T4 文献计量综述
  [5] T5 批判性 / 观点综述
  [采纳推荐] / [我想听更多区别]
```

- 用户选 **T2 / T3** 时，提醒**方法学代价**（需 PRISMA 流程图 / 预注册，耗时更长）。
- 用户选 **T4** 时，确认**数据源可用性**（WoS / Scopus 是否可访问；不可访问则降级为 T1 并用 P4 的轻量计量）。
- 用户犹豫时，展开讲**两个最相关类型**的区别，**不替用户决定**。
- 用户回复"采纳推荐"→ 使用第三步推断的推荐类型。

## 五、选择后落盘

1. 把 `review_type` 写入 HUD（见下）。
2. 生成 `{project_path}/outputs/lit-review/type_profile.md`，含：
   - 选定类型 + 选择理由（来自 P0 第三步）
   - 该类型的**写作要素清单**（从 `modules/review-types.md` 复制要点）
   - 该类型的**必备产物**与**质量门禁**（提醒后续 P4–P7）
   - 该类型的**字数目标区间**（中英双口径，从 `modules/review-types.md` 复制；写入 HUD `draft.word_count_target`）
3. 向用户确认：
   "✅ 已锁定类型为 **{T_n} {类型名}**。后续检索深度、分析维度、写作结构、
   质量门禁都会按该类型的方法学走。
   📏 写作目标字数：**{英文 word 区间} / {中文「字」区间}**（不含摘要与参考文献），
   请在 P5 撰写时对齐，P7 会按此区间做字数闸门核查。"

## 七、注意事项（反模式）

- ❌ **未选类型就开搜**：不同类综述检索深度不同，先选再搜。
- ❌ **类型与方法不自洽**：选了 T1 却在摘要写 "we systematically reviewed"——
  审稿人秒拒。类型决定措辞（见 `modules/review-types.md` 红线）。
- ❌ **替用户决定**：只给推荐 + 理由，最终选择必须用户确认（Hard Stop）。
- ❌ **中途随意改类型**：若用户中途要换类型，需回到 P0 重选并提示后续阶段可能要返工。
