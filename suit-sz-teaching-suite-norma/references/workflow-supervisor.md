# 工作流 · 督导一致性检查

以**教学督导**角色对已生成的文件把关，输出一份督导检查报告（落盘为具名 Markdown）。
四个维度：**版本 / 格式 / 内容 / 三份文件互相匹配**。只读检查，不自动修改任何 docx。

## 输入与停止条件

- 待核对文件路径，至少 1 份，理想为 3 份齐备（课标 .docx、教案 .docx 集合、授课计划 .docx）。
- 三份不全时，仍可对已存在文件做单文件检查，缺失项在报告标注"未提供"。
- **停止条件**：无法读取任何目标文件时停止并说明原因，不给出结论。

## 四维度检查

| 维度 | 检查什么 | 方法 |
|---|---|---|
| ① 版本 | 各文件的学年学期、审定/通过日期是否一致且逻辑自洽 | 文本抽取 + 比对 |
| ② 格式 | 字体族、字号、首行缩进、行距、头部标签双层 run | `scripts/validate_docx.py` 回读 XML |
| ③ 内容 | 课标含思政融入表；教案有思政栏目且能回溯课标；授课计划周次覆盖全学期；时数勾稽成立 | 结构解析 |
| ④ 三文件匹配 | 课程名 / 教师 / 教研室一致；学时一致；模块对齐；思政点全覆盖 | 跨文件比对 |

## 执行步骤

### Step 1 收集文件与判定运行级别

先跑 `scripts/check_environment.py`：

- 返回 `ready` / `partial` → 用其 `recommended_interpreter` 做 L1 完整检查。
- 返回 `needs_setup` → 改做**结构与内容层**检查（版本 / 内容 / 三文件匹配 / 时数勾稽），
  并在报告中注明"格式检查受运行环境限制未执行"，**不因此判不通过，也不停工**。

抽取文本与表格：

```python
from docx import Document

def dump(docx):
    d = Document(docx)
    paras = [p.text for p in d.paragraphs if p.text.strip()]
    tables = [[[c.text for c in r.cells] for r in t.rows] for t in d.tables]
    return paras, tables
```

### Step 2 版本检查

- 课标：课程名称、编写执笔人及编写日期、审定负责人及审定日期、适用学年学期。
- 授课计划：学年学期、任课教师、教研室主任、教研室通过日期。
- 教案：教师、课程名称、学年学期。
- **判定**：三份的学年学期须一致；授课计划的"教研室通过日期"与课标"审定日期"应逻辑自洽（至少不矛盾）。不一致 → 报告 ❌ 并列出差异。

### Step 3 格式检查

```
<python> scripts/validate_docx.py <docx> --profile course-standard|lesson|schedule
```

脚本逐项输出"位置 / 期望 / 实测"。判 FAIL 的项直接进报告问题清单；人工再抽检 10–20 个 run 复核字体族与字号。

### Step 4 内容检查

- **课标**：必须含《课程思政融入表》（知识点 / 思政融入点 / 思政案例 三列非空）。缺失 → ❌。
- **教案**：每份须有「思政融入」栏目，且能回溯到课标思政表对应行。逐份核对，未对应 → ⚠️。
- **授课计划**：周次表须覆盖学期全部教学周（1~N 周连续）；时数统计行"讲授 + 实验 = 总计"且等于课标学时分配表总计。不符 → ❌。
- **时数勾稽**：周数 × 周学时 = 授课计划计划时数 = 课标总学时；教案覆盖学时 = 覆盖周数 × 周学时。

### Step 5 三文件互相匹配（核心）

| 字段 | 课标 | 授课计划 | 教案 | 判定 |
|---|---|---|---|---|
| 课程名称 | ✓ | ✓ | ✓ | 三者必须完全一致 |
| 适用专业/班级 | ✓ | ✓ | ✓ | 一致 |
| 任课教师/教研室 | ✓ | ✓ | ✓ | 一致 |
| 总学时 | ✓ | ✓（计划时数） | 覆盖学时 | 勾稽成立 |
| 模块清单 | ✓ | 内容提要 | 单元名 | 计划与教案须覆盖课标全部模块 |
| 课程思政点 | 思政表 | 首周思政点 | 每教案思政栏目 + 教学过程落点 | 教案须全覆盖课标思政点 |

- **模块对齐**：课标每个模块都应出现在授课计划内容提要与教案单元中；遗漏 → ❌。
- **思政点覆盖**：课标思政表每一行的思政融入点，都应在至少一份教案的「思政融入」栏目或教学过程落点中体现；未覆盖 → ❌。

### Step 6 生成督导报告

落盘为 `督导检查报告-<课程名>.md`：

```markdown
# 教学文件督导检查报告 · 《XXX》
生成时间：YYYY-MM-DD
检查范围：课标 / 教案(N份) / 授课计划
总体结论：✅ 通过 / ⚠️ 有瑕疵 / ❌ 不通过

## 一、版本检查
## 二、格式检查
## 三、内容检查
## 四、三文件匹配
| 字段 | 课标 | 授课计划 | 教案 | 结论 |
## 五、问题清单（按严重度）
- [❌] 具体文件 · 位置 · 期望值 · 实测值
## 六、整改建议
```

### Step 7 回显与交付

控制台输出总体结论 + 问题清单摘要；`present_files` 给出报告与三份 docx，并明确哪些 ❌ 必须改、哪些 ⚠️ 建议改、三份文件是否互相匹配。

## 督导纪律

- 只做**只读检查 + 报告**，不自动修改任何 docx。
- 凡判 ❌ 须指明具体文件、位置、期望值与实测值。
- 不臆造"通过"：未实际抽取核对的项标注"未验证"。
- 三份文件任一缺失时，不匹配项标注"缺对照文件"，不盲目判通过。
