# 用户核查清单 · 教材 → 课件

> norma-textbook-deck · 流程型标配
> 用法：skill 跑它的流程，你拿这张清单监督。每行一个"skill 应完成的动作 + 你怎么核查 + 应见哪个落盘文件"。
> 勾选原则：**没见到对应落盘文件，就不算完成**。

---

## P1 · 读源文 + 抽代码 + 反推规律

| # | skill 应完成 | 我怎么核查 | 应见落盘文件 |
|---|---|---|---|
| 1.1 | 完整读源 md，列全元素清单 | 清单里的板块与源 md 目录逐条对上 | 无（对话呈现） |
| 1.2 | 抽出全部代码块，按小节归档 | 打开 txt，小节标题与代码块数量对得上 | `第N章_xxx_实例代码.txt` |
| 1.3 | 反推/核对七条抽取规律 | 与你印象中的既有 PPT 风格一致 | `modules/extraction-rules.md`（如更新） |
| 1.4 | 配色选定并硬停确认 | 你确认过一次配色 | `deck-state.json` 的 `scheme` |

## P2 · 页面大纲 + 空白 deck

| # | skill 应完成 | 我怎么核查 | 应见落盘文件 |
|---|---|---|---|
| 2.1 | 排好页面大纲（页序 + 每页要点） | 页序符合教学弧线，一页一个点 | `slide_plan.json` |
| 2.2 | 建在线空白 deck 并通知 | 点开链接能看到空 deck | url 出现在对话 |
| 2.3 | 配图只搜不生成 | 图片是真实实拍素材，非 AI 生成 | `images/` 下的图片文件 |

## P3 · 逐页闭环

| # | skill 应完成 | 我怎么核查 | 应见落盘文件 |
|---|---|---|---|
| 3.1 | 每页写 XML | 文件数 == 计划页数 | `chN_ppt/slide-01.xml`…`slide-NN.xml` |
| 3.2 | 每页 lint 到 0 错才提交 | 抽查任意页，lint 无 error | `.lint.tmp.json`（可覆盖） |
| 3.3 | 每页记 slide_id | 页数与在线 deck 一致 | `deck-state.json` 的 `P3_pages` |
| 3.4 | 每页有讲稿 note | 打开任意页，note 有 3–5 句 | 各 slide XML 的 `<note>` |
| 3.5 | 含图页回读核页数 | 页数无多出 | 验收时核对 |

## P4 · 三重验收 + 交付

| # | skill 应完成 | 我怎么核查 | 应见落盘文件 |
|---|---|---|---|
| 4.1 | 服务端页数 + 顺序核对 | 在线 deck 页数 == 计划，顺序对 | `server.xml` |
| 4.2 | 全文 lint = 0 错 | 报告 0 错 | `.lint.true.json` |
| 4.3 | pptx 完整性（zip + 页数 + 图数） | 能打开、页数对 | `第N章_xxx.pptx` |
| 4.4 | 三件套落盘 | 教材目录里有 pptx 与代码 txt | `第N章_xxx.pptx`、`_实例代码.txt` |

---

## 一票否决项（任一项不满足即可打回）

- ❌ PPT 正文出现了整段代码
- ❌ 配图是 AI 生成的（非真实素材）
- ❌ 页数与计划不符且未说明
- ❌ 全文 lint 有 error
- ❌ 交付缺 pptx 或代码 txt
