# P6 · 内容撰写（Pattern 5 版）

> AFP Skill Creator · Stage 06
> 目的：把 P3 显性化的方法论 + P4 的结构设计 + P5 的 frontmatter 落成真正的文件内容——尤其是 AFP 步进式引导逻辑的具体写法

---

## 一、写作顺序（自底向上 + 回填）

推荐顺序，避免主控与子文档脱节：

```
Step 1 · 主控骨架     按 P4 §三骨架 + P5 frontmatter 搭出 SKILL.md 空架子
                      （HUD 骨架 + 空路由表 + 通用指令表，先不填业务）
Step 2 · 逐个 stage   按方法论步骤顺序写 stages/01 → 02 → …（每个用 templates/stage-md-template.md）
Step 3 · 回填主控     stage 全部写完后，回填主控的阶段路由表 + 按需模块表
Step 4 · modules      写按需模块（如有）
Step 5 · README       最后写使用说明
```

**每完成一个 Step 都是一次 Hard Stop**——本 skill 会展示写好的文件让用户确认，`Next` 后才写下一个。**绝不一次性生成全部文件。**

---

## 二、AFP 步进式内容七要素（核心规范）

用户的 skill 要成为"步进式 AFP skill"，每个 stage 的内容必须落实以下七要素。这七要素直接对应 AFP-SPEC 条款，P8 合规检查逐条验收。

### 要素 1 · 原子级单步输出

一次交互只推进**一个决策单元**——一个阶段、一个方案选择、一份产出物。

- ✅ 正确："P2 完成，产出主题矩阵如下，确认后进入 P3"
- ❌ 错误：一口气输出主题矩阵 + 综述骨架 + 成稿初稿（用户失去过程控制权，错误会级联）

写法：在 stage 文档里明确"本阶段只产出 {X}，不代替后续阶段"。

### 要素 2 · Hard Stop（AFP-SPEC §5）

每个阶段结尾必须硬停止，等用户 `Next` / `Back` / `Edit` 才动。

写法：每个 stage 文档结尾放统一格式的交付确认单：

```
╭─ {skill_name} · P{N} {阶段名} 完成 ─────────────╮
│ 📊 {本阶段关键状态字段}
│ ✅ 产出：{artifact}
│ 📍 下一步：P{N+1} - {next_stage_name}
│ 👉 NEXT：Next 继续 / Back 回退 / Edit 修改
╰──────────────────────────────────────────╯
```

并加一句纪律条款："**即使结果非常明确，也不允许自动进入下一阶段。**"——没有这句，Claude 在长对话里会越权自动推进。

### 要素 3 · HUD 心跳信号

每次 Hard Stop 同步刷新 HUD 状态快照，让用户随时知道"走到哪了、还剩什么"。

写法：主控定义 HUD JSON 骨架（见 P4 §三）；每个 stage 文档说明本阶段更新哪些字段；确认单里带出关键字段。用户说 `Status` 时输出完整 HUD。

### 要素 4 · 多方案选择（关键决策点）

方向性决策（理论定位、叙事结构、标题方案等）不替用户拍板——给 2-3 个方案，各带理由与代价，用户选。

写法：在 stage 文档里标出哪几步是"方案型决策"，规定输出格式：

```
方案 A：{描述} —— 优势：{...} / 代价：{...}
方案 B：{描述} —— 优势：{...} / 代价：{...}
👉 请选择：A / B / C（或说出你的调整）
```

来源：P3 五问的"问 3 判断标准"里答不出唯一标准的步骤，就是方案型决策点。

### 要素 5 · Evidence Chain（AFP-SPEC §6）

事实性输出必须可溯源：引用给出处、数据给来源、无法验证的标 `unverified`。

写法：在涉及事实产出的 stage 里写明验证动作（如"写作前用 `afp-shared-cnki-search` 逐条验证引用"），并对照 `modules/domains/{domain}.md` 的领域证据链标准。

### 要素 6 · 断点续传

每次 Hard Stop 后状态写盘，新对话可 `Continue {project_path}` 续跑。

写法：主控写入断点续传节（格式见 `modules/continuation-protocol.md`）；每个 stage 确认单产出的 artifact 落盘到 `{project_path}/stage-outputs/`。

### 要素 7 · 产物落盘（工程化命门，对应 O5）

每个产出实质内容的 stage，其产物**不能只显示在对话里**，必须**落盘为具名文件**（表 / 稿 / 脚本 / 图 / 数据 / 交接包）。对话会压缩、会结束，磁盘不会。

写法：在每个产出类 stage 的"输出 schema"节里，除字段 / 格式外，显式写明"**落盘为 `{project_path}/stage-outputs/{具名文件名}`**"；引导逻辑让 Claude 产出后**真正写盘、回报绝对路径**，不只在对话里打印。

判据：换一个全新对话、只凭磁盘上这些文件，能不能接着往下干——能，才算真落盘。

⚠️ 与要素 6 区分：要素 6 的状态盘（state.json）是为**断点恢复**；要素 7 的产物落盘是让产出成为**可复用 / 可交接 / 可复现**的知识资产，两者都要。P8 由 O5 逐 stage 验收。

## 三、stage 子文档标准骨架

每个 stage 文档统一用这个骨架（完整模板见 `templates/stage-md-template.md`）：

```markdown
# P{N} · {阶段名}

> {skill 全称} · Stage {NN}
> 目的：{本阶段一句话目的}

## 一、本阶段做什么（边界声明）
（只产出 {X}；不做 {后续阶段的事}——单步输出边界）

## 二、引导逻辑
（方法论该步骤的具体执行：提问序列 / 分析动作 / 判断标准）

## 三、方案型决策点（如有）
（哪个决策给多方案，方案输出格式）

## 四、输出 schema
（本阶段产出物的结构定义——字段 / 章节 / 格式）

## 五、Hard Stop · 交付确认单
（统一格式确认框 + "不允许自动推进"纪律条款）

## 六、反模式警告
（本阶段 3-8 条易错点，源自 P3 五问的"失败点"）

---
*P{N} 完成后，主控加载 stages/{NN+1}-{next}.md*
```

**纪律**：子文档无 frontmatter；结尾必须有指向下一 stage 的路由脚注（断链 = P8 不通过）。

## 四、引导话术写作规范

1. **口令一致**：全 skill 只用主控通用指令表里的口令（Next / Back / Edit / Skip / Export / Status / Continue），stage 里不发明新口令
2. **话术可直接执行**：写给 Claude 的指令用祈使句（"询问用户…" / "输出以下确认单"），写给用户看的话术放在代码块里原样输出
3. **首次上手引导**：主控的首次触发话术 100-200 token，说清"我是谁、能干什么、先回答我几个问题"——参考本 skill 主控 §首次上手
4. **温度**：专业但不冰冷；领域行文规范对照 `modules/domains/{domain}.md`
5. **不承诺做不到的事**：话术里的每个功能点必须有对应的 stage / module 支撑
6. **用独家语料校准手感**（有语料时）：P3 收集、P4 挂载的语料要真正接进流程——每个**产出类 stage** 的引导逻辑里写明"生成前 Read `modules/exemplars.md` 对应节的 90 分样例作 few-shot 参照，输出后与样例对齐自检"；反面样例（含打回理由）写进该 stage 的反模式清单。语料挂了但没有任何 stage 去 Read = 白挂

## 五、Token 预算

| 文件 | 预算 | 超了怎么办 |
|---|---|---|
| SKILL.md 主控 | 2000-2500 token | 内容下沉到 stages/ 或 modules/（薄路由铁律） |
| 单个 stage | 1500-4000 token | 拆出按需 module，stage 里只留主流程 |
| 单个 module | 不限但按需 Read | 确保只在触发条件下加载 |
| 首次上手话术 | 100-200 token | 砍到只剩必要提问 |

## 八、反模式警告

内容撰写阶段常见错误：

- ❌ **一次性生成全部文件**：不走 Step 1-5 的分步确认，一口气吐完——用户没有任何过程控制，错一处错全套
- ❌ **stage 越界**：P2 的文档里顺手把 P3 的活也干了——破坏单步输出，后面阶段变成空壳
- ❌ **确认框格式漂移**：每个 stage 自己发明确认单样式——用户失去稳定的"心跳"感知
- ❌ **缺"不允许自动推进"条款**：长对话里 Claude 会自动连跳三个阶段
- ❌ **方案型决策写成单方案**：替用户拍板方向性问题——AFP 是"用户掌舵，agent 划桨"
- ❌ **话术承诺超出能力**：首次引导说"我能帮你投稿"但没有任何投稿 stage
- ❌ **主控写成教材**：把方法论原理长篇写进 SKILL.md——原理放 modules/，主控只做路由
- ❌ **忘记路由脚注**：stage 结尾不写"完成后加载 xx"——流程走到一半断链
