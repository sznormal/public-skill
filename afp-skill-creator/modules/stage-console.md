# 阶段控制台（Stage Console）· AFP 流水线 skill 通用控制块

> 适用：任何"多阶段、有 Hard Stop、长流程"的 AFP skill（研究流水线、写作流水线、
> 审查流水线、数据处理流水线等）。与 `continuation-protocol.md`（断点续传/抗压缩）互为补充：
> 断点续传解决"换对话能不能接着干"，阶段控制台解决"跑的时候看得见、查得到、退得回"。

AFP-SPEC 已经要求流水线 skill 自带「状态管理 + 断点续传」。但光有 HUD JSON 不够——
用户要**看得见当前在哪**、**查得到每阶段做了什么决定**、**出错了能退回重做**。
本模块给出一套可直接套用的控制块，三件事：

1. **仪表盘（Dashboard）** — 说明现在的运行阶段（全阶段进度看板）
2. **阶段结果台账（Ledger）** — 记录每阶段跑了什么（决策/指标/产物/检查点）
3. **回退（Rollback）** — 必要时退得回（快照 + 状态恢复，非破坏性）

---

## 一、数据模型（写入 `{project}/<状态目录>/`）

```
<状态目录>/
├── hud_state.json          # 全局状态（meta.current_stage + 各领域聚合字段）
├── stage_ledger.json       # 阶段结果台账（数组，每阶段一条）
└── stage_snapshots/        # 每阶段产物快照
    ├── P0_<时间戳>/
    ├── P1_<时间戳>/
    └── ...
```

`stage_ledger.json` 每条记录字段（与 HUD 的 `history.completed_stages` 互补，后者只记"完成"，台账记"做了什么"）：

```json
{
  "stage": "P3",
  "name": "文献筛选与分类",
  "ts": "2026-10-07T10:00:00",
  "status": "done",            // done | rolled_back
  "summary": "文献筛选完成",    // ≤10 字阶段小结，显示在仪表盘每行后
  "decision": "用户确认筛选标准 + 逐篇选文理由",
  "key_metrics": {"found": 142, "seed_recall": "58%"},
  "artifacts": ["screened_literature.md", "screening_decisions.md"],
  "checkpoint": "P4 Hard Stop 待用户确认分析维度",
  "note": ""
}
```

> 落盘思维（理念 6）：台账 + 快照是"可复核、可回退"的依据——换一个全新对话，
> 只凭这两个文件就能接着干。**判据**：换对话只靠磁盘文件能不能说清"跑到哪、为啥这么定、退到哪"？能，才算真落盘。

---

## 二、仪表盘（渲染规范）

每次 **Hard Stop 输出** 与用户说 **`Status`** 时，必须渲染全阶段进度看板（ASCII 盒即可）：

```
╭─ <skill名> · 阶段仪表盘 ──────────────────────────╮
│ P0 <阶段名>     ✅ done        已定综述类型
│ P1 <阶段名>     ✅ done        制定检索策略
│ P2 <阶段名>     🔄 active      多库检索完成
│ P3 <阶段名>     ⏳ pending      —
│ ...（其余阶段同格式；rolled_back 阶段显示 ↩️ 且小结为 —）
│ 当前阶段：P2 · <阶段名>
│ 进度：2/N 阶段完成
╰──────────────────────────────────────────────────╯
```

**每行阶段后必须附「≤10 字阶段小结」**（来自台账 `summary` 字段）——让用户一眼回看
"每个阶段到底完成了什么主任务"，而不是只看到状态勾。无小结的阶段显示「—」。

状态四态：
- `✅ done` — 阶段号已入 `hud_state.json` 的 `history.completed_stages`
- `🔄 active` — 阶段号 == `meta.current_stage`
- `⏳ pending` — 未到
- `↩️ rolled_back` — 被回退清掉（台账保留为 `rolled_back` 供审计）

阶段名与编号必须与主控的"阶段路由表"完全一致（单一真相源）。

---

## 三、每阶段收尾动作（强制，替代零散的"更新 HUD"）

每个阶段子文档的收尾段统一执行，顺序不可省：

1. **写产物** — 本阶段实质产出落盘为具名文件（落盘思维）
2. **记台账** — 追加一条 `stage_ledger.json` 记录（**必须带 `summary` ≤10 字阶段小结** + 决策 + 关键指标 + 产物 + 下一检查点）
3. **做快照** — 对 `<状态目录>/` 做产物快照存入 `stage_snapshots/<Pn>_<时间戳>/`
   （排除 `hud_state.json` / `stage_ledger.json` / 快照目录自身，避免递归）
4. **更 HUD** — 写 `current_stage`、对应领域字段、`history.completed_stages`
5. **渲染仪表盘** — 见第二节
6. **输出 Hard Stop 卡** — 见各 skill 既定格式

无脚本能力/离线环境：按上述字段手工改 `hud_state.json` + `stage_ledger.json` 等价操作，
不可因为"没跑脚本"就跳过台账与快照。

---

## 四、回退（Rollback）协议

用户说 **`Back`**（或"回退到 Pn"）时，**默认安全、非破坏性**：

1. **dry-run** — 先打印回退计划：目标阶段、将被标记 `rolled_back` 的后续阶段、
   将恢复的最新快照路径；**不改动任何文件**。
2. **确认后执行** — 用户确认（或显式 `--apply`）：
   - 恢复目标阶段**最新**快照覆盖工作产物；
   - 回写 HUD（`current_stage` = 目标；`completed_stages` 截到目标及之前）；
   - 把后续阶段台账标记 `rolled_back`。
3. **无快照兜底** — 若目标阶段无快照：仅回写 HUD/台账、不恢复产物，
   并明确告知用户"无快照可恢复，需手动重做该阶段产物"。

⚠️ 回退是"重做"，不是"抹除历史"——被回退阶段的台账保留为 `rolled_back` 供审计。
不要删除快照目录（它是回退物料，也是过程证据）。

⚠️ **回退后必须提醒用户重新走一遍后续流程**：dry-run 计划与执行结果都要列出
"需重走：P{n+1} → … → 当前阶段"，并提示"从下阶段 (P{n+1}) 开始逐阶段重做产物、重新记台账/快照"。
agent 在回退确认后**必须把这个提醒原样转述给用户**，不能只回一句"已回退"——否则用户会误以为
后续阶段仍有效，带着被清掉的状态继续往下走。

## 五、实现建议（纯标准库，零依赖）

阶段控制台本质是"文件读写 + 复制"，用 skill 生成的一小段脚本即可机械化，
不必每次手工做。参考实现（与 `norma-lit-review/scripts/stage_ctl.py` 同构）：

- `dashboard` — 读 `hud_state.json` + `stage_ledger.json`，按第二节打印看板（含每行 `summary`）
- `log` — 追加台账记录（接收 `--summary` ≤10 字；超长截断并警告，未提供则警告；同时把阶段号并入 `completed_stages`、推进 `current_stage`）
- `snapshot` — `shutil.copytree`/`copy2` 复制产物到带时间戳子目录
- `back` — dry-run 打印计划（含"需重走后续流程"提示）；`--apply` 恢复快照 + 回写 HUD + 标记台账 + 打印重走提醒

**规则**：只用 Python 标准库（`json`/`shutil`/`os`/`argparse`/`datetime`），不引入 pip 依赖、
不要求 venv——保证任意环境（含离线/受限）都能跑。解析 `--project` 时用 parent parser 注入子命令，
否则 argparse 子命令不继承顶层参数（实战坑）。

## 六、反模式（本模块专属）

- ❌ 只有内部 HUD JSON、不渲染可见仪表盘 → 用户不知道跑到哪（本模块要解决的头号问题）
- ❌ 仪表盘只显示状态勾、不显示「≤10 字阶段小结」→ 用户回看不出"每阶段干了什么主任务"
- ❌ 阶段决策只存在对话里、不写台账 → 换对话/换人无法复核"为什么这么定"
- ❌ `Back` 无行为定义、无快照 → 口头"回退"实际无法恢复产物与状态
- ❌ 回退后只回"已回退"、不提醒重走后续流程 → 用户误以为后续阶段仍有效，带脏状态继续
- ❌ 回退直接删文件/删快照 → 破坏可审计性与重试能力
- ❌ 把 `<状态目录>` 自身快照进去 → 递归爆目录，排除状态文件与快照目录
