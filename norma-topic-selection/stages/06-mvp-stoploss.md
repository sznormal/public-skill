# P6 · MVP 最小验证与止损

> 目标：用 4–6 周、极小成本，验证这题"到底成不成立"——**在投入完整系统之前**。

## 一、MVP 六要素（缺一不可）

1. 一个公开或容易获得的数据集
2. 一个公认基线（**能复现**的）
3. 一个最简单的改进方案
4. 一个主要评价指标
5. 一个最关键的困难条件
6. 一次可重复的实验

## 二、MVP 要回答的五个问题

- 问题是否**真实存在**（不是检索错觉）？
- 基线是否**能复现**（复现不了 = 选错基线，不是选错题）？
- 改进方向是否有**初步正向信号**？
- 实验成本是否**在预算内**？
- 研究假设是否**需要修改或缩小**？

## 三、止损规则（**开始前就写好，不是跑不出来才想**）

| 触发条件 | 处置 |
|---|---|
| 基线无法复现 | 换有代码和明确配置的基线；不换题 |
| 改进方法无效果 | 转向边界分析/消融分析/效率研究（分析型退路） |
| 数据量不足 | 缩小研究问题或改用公开数据 |
| 设备条件不满足 | 先做仿真或离线实验 |
| 假设被证伪 | 收缩到能成立的那一小步，或转 P3 重选 |
| 成本超预算 | 缩模型/缩数据规模/换代理指标 |

**明确写出"何时停止一个不可行的方案"。** 研究计划应允许缩小题目或转变问题，而不是把所有风险推迟到最后。

## 四、退路设计（进评分卡的"退路"维度）

回答：**如果核心假设被证伪，我手上的数据和副产物还能支撑什么？**

- 边界条件分析 → 负结果也有发表价值（目标刊是否接受负结果，在 P0 已查）；
- 消融分析 → 方法分析型论文；
- 数据集/协议 → 若你在统一口径上花了力气，这本身是可交付物；
- 完全不成立 → 记录在案，换题成本远低于硬撑三个月。

## 五、产出

- `outputs/topic-selection/mvp_plan.md`：六要素 + 五个问题的答案预期 + 止损规则 + 退路 + 时间盒（4–6 周）

## 六、Hard Stop

**在开始任何实验之前**，向用户逐条确认止损规则已书面固定，并确认：
1. 时间盒长度（默认 4–6 周）与中止判据；
2. 退路是否真的成立（数据/设备是否支撑）；
3. 若 MVP 不通过，回 P3 还是换方向。

MVP 出结果后回到用户：
- 通过 → 进 P7，**并按月复跑门 E（撞题复查）**；
- 不通过 → 回 P3 补料/换题，**不要在原题上加班加点抢救**。

## 七、常见坑

- ❌ 不做 MVP 直接上完整系统 → 三个月后发现基线都跑不通；
- ❌ 止损规则事后补 → 事后写的止损规则永远不会被执行；
- ❌ MVP 只做一次 → 至少做一次可重复实验，否则无法区分"信号"与"噪声"；
- ❌ 忽略"能改小结论"的止损 → 收缩范围往往比换题更快落地。
