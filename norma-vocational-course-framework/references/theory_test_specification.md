# 理论测试题出题规范

## 概述

每个任务的理论测试题独立为一个 `09_理论测试题.md` 文件，基于该任务的 `02_知识准备.md` 实际内容出题，用于检验学生对理论与实操知识的掌握程度。

### 核心原则：理实并重 + 渐进式范围

本规范遵循两大核心原则：

1. **理实并重（双轴布鲁姆）**：每道题同时标注布鲁姆认知层次（L1-L6）和认知维度（理论认知/实操推理），两类维度各占约50%，确保理论考试不沦为纯背诵测试。
2. **渐进式范围约束**：每个任务的出题范围 = 本任务知识 + 之前所有任务知识。严禁引用后续未学任务的知识点。改错题的错误类型也不得超出已学范围。

## 试卷结构

| 题型 | 题量 | 每题分值 | 总分 |
|------|------|----------|------|
| 单选题 | 10题 | 3分 | 30分 |
| 填空题 | 5题 | 4分（每空2分，每题1-2空） | 20分 |
| 简答/改错/思政思考题 | 5题 | 10分 | 50分 |
| **合计** | **20题** | | **100分** |

## 双轴布鲁姆认知分层框架

### 为什么需要双轴

职业本科课程理论与实操学时比约为 18:46（理实并重），理论测试不能仅考概念背诵。每道题需同时标注：

- **布鲁姆层次**（L1记忆 ~ L6创造）：认知深度
- **认知维度**（理论认知 / 实操推理）：知识类型

### 双轴定义

| 维度 | 占比 | 含义 | 出题特征 |
|------|------|------|----------|
| **理论认知** | ~50% | 概念、原理、语法、API参数等纯知识 | "X是什么？""解释Y的原理""对比A与B" |
| **实操推理** | ~50% | 输出预测、场景决策、代码分析、错误诊断 | "执行X后输出什么？""场景Y应选哪个命令？""找出代码中的错误" |

### 布鲁姆6级 x 双轴映射

| 层次 | 理论认知维度 | 实操推理维度 | 目标占比 |
|------|------------|------------|---------|
| L1 记忆 | 回忆概念/命令名/语法/API签名 | 识别输出格式/辨认工具用途/回忆操作步骤 | 15% |
| L2 理解 | 解释原理/对比概念/分类归纳 | 解读命令输出/说明操作含义/对比虚实差异 | 20% |
| L3 应用 | 给定场景选命令/API/参数 | 预测命令输出/选择操作步骤/给定条件推导 | 25% |
| L4 分析 | 调试代码/找出竞态条件/归因 | 故障诊断/根因分析/改错题 | 20% |
| L5 评价 | 评判方案优劣/论证技术选择 | 评估代码质量/优化性能/思政思考 | 10% |
| L6 创造 | 设计新架构/编写完整模块 | 构建完整系统/集成多模块/编写可运行代码 | 10% |

### 各题型双轴分配要求

**单选题（10题）双轴分配**：

| 维度 | L1 | L2 | L3 | L4 | 小计 |
|------|-----|-----|-----|-----|------|
| 理论认知 | 2题 | 2题 | 1题 | 0-1题 | 5-6题 |
| 实操推理 | 0-1题 | 1题 | 2题 | 1题 | 4-5题 |

**填空题（5题）双轴分配**：

| 维度 | L1 | L3 | 小计 |
|------|-----|-----|------|
| 理论认知 | 2题 | 0-1题 | 2-3题 |
| 实操推理 | 1题 | 1题 | 2-3题 |

**简答/改错/思政题（5题）双轴分配**：

| 题号 | 题型 | 布鲁姆层次 | 维度 | 说明 |
|------|------|-----------|------|------|
| 第1题 | 简答题 | L2 理解 | 理论认知 | 解释概念或原理 |
| 第2题 | 改错题 | L4 分析 | 实操推理 | 找出代码/命令错误并修正 |
| 第3题 | 简答题 | L3 应用 | 实操推理 | 给定场景分析或方案选择 |
| 第4题 | 思政思考题 | L5 评价 | 实操推理 | 结合工控安全/自主可控/工匠精神评价论证 |
| 第5题 | 综合设计题 | L6 创造 | 实操推理 | 设计方案或编写完整代码 |

> 第5题必须为L6创造级（设计/编写），不能仅是"简述"或"说明"

## 渐进式知识范围约束

### 范围定义

每个任务的出题范围 = **本任务 `02_知识准备.md` 内容** + **之前所有任务的 `02_知识准备.md` 内容**。

**严禁引用后续未学任务的知识点。**

### 三阶段范围与可达布鲁姆层次

| 阶段 | 任务 | 累计知识范围 | 可达Max Bloom | 改错题限制 |

### 范围约束实例

**正确示例（P3T1 文件IO测试）**：
- 可以引用P1的Shell命令（如`cat /proc/self/fdinfo/3`查看文件描述符）
- 可以引用P2的GCC编译知识（如`gcc -g -O0`编译选项）
- 改错题可以包含`open()`返回值未检查、`read()`参数错误等
- L4分析题可以让学生分析`fork()`后文件描述符的继承关系（P3T2知识？不，fork在P3T1范围内不涉及）

**错误示例（P3T1 文件IO测试）**：
- 不得引用P3T2的`fork()`/`exec()`知识
- 不得引用P4T1的内核模块知识
- 不得在改错题中使用多线程相关的错误

## 出题流程

### Step 1：读取知识准备内容（含前序任务）

**1a. 读取本任务知识准备**：
```
Read {任务目录}/02_知识准备.md
```
全面梳理知识准备中的核心知识点，提取可考查的概念、命令、参数、原理。

**1b. 确认前序知识范围**：
查阅「渐进式知识范围约束」中的「各任务出题范围速查表」，确认本任务可引用的前序知识。如有需要，读取前序任务的 `02_知识准备.md` 中相关章节，确保引用准确。

**1c. 标注知识边界**：
在出题前，明确列出「可用知识清单」和「禁用知识清单」，避免无意中超纲。

示例（P3T1 文件IO）：
- 可用：P1（命令行/权限/管道）、P2（GCC/Makefile/GDB）、P3T1（open/read/write/lseek/stat/mmap/errno）
- 禁用：P3T2（fork/exec/IPC）、P4（内核模块/设备树）、P5-P6（移植/产品集成）

### Step 2：编制单选题（10题）

**考查范围**：基础概念、命令参数、术语定义、原理解释、场景应用

**布鲁姆层次分配**：L1记忆3-4题 + L2理解3-4题 + L3应用2-3题 + L4分析1题

**出题要求**：
- 4个选项（A/B/C/D），必须有迷惑性，不能一眼排除
- 干扰项应为常见错误理解或易混淆概念
- 每题聚焦一个知识点，不要混合多个知识点
- 避免"以上都是/以上都不是"型选项
- **L3应用级题目必须给出具体场景**（如"某开发者需要..."、"在以下场景中..."）

**L1记忆级示例**：
```markdown
1. 在Linux中，以下哪个命令用于查看当前工作目录的绝对路径？
   A. ls   B. pwd   C. cd   D. dir
```

**L3应用级示例**：
```markdown
3. 某开发者需要将文件权限设置为"所有者可读写执行、组用户可读执行、其他用户只读"，
   应使用以下哪个命令？
   A. chmod 754 file   B. chmod 744 file   C. chmod 644 file   D. chmod 755 file
```

**L4分析级示例**：
```markdown
7. 以下代码执行后，变量count的最终值是多少？
   int count = 0;
   for (int i = 0; i < 3; i++) {
       if (fork() == 0) { count++; exit(0); }
   }
   A. 0   B. 1   C. 3   D. 7
```

**实操推理维度示例（L2理解-实操）**：
```markdown
5. 执行命令 `ls -l /etc/passwd` 后，输出行的第一个字段为 `-rw-r--r--`。
   其中 `r--` 代表哪类用户的权限？
   A. 文件所有者   B. 文件所属组   C. 其他用户   D. 超级用户
```

**实操推理维度示例（L3应用-实操）**：
```markdown
8. 某开发者执行 `chmod 640 config.ini` 后，发现同组用户无法读取该文件。
   以下哪个命令可以修正此问题？
   A. chmod 644 config.ini   B. chmod 660 config.ini
   C. chmod 604 config.ini   D. chmod 646 config.ini
```

### Step 3：编制填空题（5题）

**考查范围**：关键术语、命令名、参数名、概念定义、数值常量、条件计算

**布鲁姆层次分配**：L1记忆3-4题 + L3应用1-2题

**出题要求**：
- 每题1-2个空，每空2分
- 空格处填写的内容必须唯一确定，不留歧义
- 避免过长的填空内容（超过5个词的不适合做填空）
- **L3应用级题目需给定条件让学生推导或计算**

**L1记忆级示例**：
```markdown
1. Linux系统中，______空间是应用程序运行的区域，而______空间是内核运行的区域。
```

**L3应用级示例**：
```markdown
3. 某文件的权限为 rwxr-xr--，对应的数字表示法为______。
   若要用chmod命令将组用户权限改为可读写，应执行 chmod______ 文件名。
```

**实操推理维度示例（L2理解-实操）**：
```markdown
4. 执行 `ls -l` 后某文件显示为 `drwxr-xr-x`，该文件类型为______，
   所有者的权限用数字表示为______。
```

**实操推理维度示例（L3应用-实操）**：
```markdown
5. 某开发者需要用Shell脚本判断文件是否存在且可执行，测试条件应写为
   if [ ______ ]; then ...（填写test表达式）
```

### Step 4：编制简答/改错/思政题（5题）

**题型配比与布鲁姆层次要求**：

| 题号 | 题型 | 布鲁姆层次 | 说明 |
|------|------|-----------|------|
| 第1题 | 简答题 | L2 理解 | 考查概念理解或原理阐述 |
| 第2题 | 改错题 | L4 分析 | 给出错误代码/命令，要求找出并修正 |
| 第3题 | 简答题 | L3 应用 | 给定场景分析或方案选择 |
| 第4题 | 课程思政思考题 | L5 评价 | 结合工控安全/自主可控/工匠精神评价论证 |
| 第5题 | 综合设计题 | L6 创造 | 设计方案或编写完整代码（不能仅"简述"） |

> 第5题必须为L6创造级：要求学生设计模块结构、编写完整代码、或构建解决方案，而非仅"说明"或"列出"

**改错题出题要求**：
- 给出一段包含1-3处错误的代码或命令
- 要求学生：找出错误 → 写出修正 → 说明原因
- 错误类型建议：语法错误、逻辑错误、安全规范错误、参数误用

**改错题示例**：
```markdown
2. 以下Shell脚本存在错误，请找出所有错误并修正，说明原因。
   ```bash
   #!/bin/sh
   name = "test"
   if [ $name = "test" ]; than
       echo "match"
   fi
   ```
```

**思政思考题出题方向**：

| 方向 | 示例主题 |
|------|----------|
| 工控安全 | 为什么工控系统不能随意使用root权限运行服务？ |
| 自主可控 | 讨论国产芯片（如RK3568）在嵌入式领域的意义 |
| 工匠精神 | 从代码规范看工程师的职业素养 |
| 安全意识 | rm -rf事故案例分析与防范意识 |
| 人机协同 | AI辅助开发时代工程师的核心竞争力 |

### Step 5：编写参考答案

**必须逐题提供参考答案**：

- **单选题**：给出正确选项字母 + 1-2句简要解析
- **填空题**：给出标准答案，如有多个等价表述需列出
- **简答题**：给出完整参考答案，包含要点列表
- **改错题**：指出错误位置 → 给出修正代码 → 解释错误原因
- **思政题**：给出参考思路和要点，不设唯一标准答案

## 难度分布（基于双轴布鲁姆认知分层理论）

### 三级难度与双轴布鲁姆映射

| 难度 | 占比 | 布鲁姆层次 | 理论认知示例 | 实操推理示例 |
|------|------|-----------|------------|------------|
| 基础题 | 35% | L1+L2 | 概念回忆、命令名、参数含义 | 识别输出格式、解读命令输出 |
| 中等题 | 45% | L3+L4 | 给定场景选API、对比方案 | 预测输出、改错、故障诊断 |
| 综合题 | 20% | L5+L6 | 评判方案优劣、设计架构 | 评估代码质量、编写完整代码 |

> 与传统学术型 60/30/10 相比，理实并重型课程降低记忆占比、提升应用分析占比，反映职业本科对实操推理能力的重视。

### 渐进式难度调节

难度分布应随课程进度动态调整：

| 阶段 | 基础(L1+L2) | 中等(L3+L4) | 综合(L5+L6) | 说明 |
|------|------------|------------|------------|------|
| P1-P2（入门起步） | 45% | 40% | 15% | 知识范围窄，L6题可简化为"编写简短脚本/函数" |
| P3-P4（核心能力） | 35% | 45% | 20% | 标准分布，L6题可要求"设计模块/编写驱动" |
| P5-P6（综合实战） | 30% | 45% | 25% | 全课程范围，L6题可要求"跨项目综合设计" |

### 各题型布鲁姆层次分配要求（详见上方双轴分配表）

> 单选题、填空题、简答题的双轴分配要求已在「双轴布鲁姆认知分层框架」章节中详细定义，此处不再重复。
