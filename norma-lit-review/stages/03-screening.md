# P3 · 文献筛选与分类

> Norma理工科文献综述 · Stage 03
> 目标：按纳排标准筛选文献，按主题聚类，形成最终纳入清单

---

## 一、两轮筛选

### 第一轮：标题+摘要筛选（快速扫读）

对 P2 产出的全部文献，读取标题和摘要，逐篇判断相关性：

| 判断 | 标准 | 操作 |
|------|------|------|
| ✅ 相关 | 标题/摘要中包含 ≥2 个 P1 识别的核心概念/关键词 | 进入第二轮 |
| ⚠️ 待定 | 只有 1 个关键词匹配，或摘要模糊 | 标记，人工判断 |
| ❌ 不相关 | 关键词匹配为误匹配（如学术概念与商业产品重名） | 剔除 |

**理工科特殊处理**：
- 纯理论论文 vs 工程实现论文 → 分别标记，后续分析用
- 综述论文 → 标记为"snowball"（其参考文献是金矿）
- 数据集/基准测试论文 → 标记为"benchmark"

### 第二轮：全文可获取性检查

对第一轮筛选后的文献，验证能否获取全文：
- 开放获取（OA）→ 直接通过
- 机构订阅 → 标注，可能需要用户手动下载
- 付费墙 → 优先替代为 OA 版本或预印本

## 二、主题聚类

使用文献的标题+摘要+关键词，做无监督聚类（3-N 个簇）：

### 聚类维度（理工科）
1. **技术方法聚类**：同一技术路线的文献归为一组（如"基于深度学习的方法""传统图像处理方法"）
2. **应用场景聚类**：同一应用领域的归为一组（如"实验教学平台""工业检测""机器人视觉"）
3. **研究范式聚类**：实验验证 / 仿真模拟 / 理论分析 / 系统设计

### 聚类输出
为每个簇命名，生成主题树：

```
主题A：深度学习在嵌入式视觉中的应用（{n}篇）
  ├── 子主题A1：轻量化模型部署（{n}篇）
  ├── 子主题A2：实时推理优化（{n}篇）
  └── 子主题A3：边缘设备适配（{n}篇）
主题B：实验教学平台的视觉交互设计（{n}篇）
  ...
```

## 三、核心文献标记

自动识别高价值文献并标记：

| 类型 | 判断标准 | 标记 |
|------|---------|------|
| 🔑 奠基性文献 | 被引次数 > 100 且发表较早 | `[FOUNDATION]` |
| 🔥 前沿文献 | 近 2 年发表 + 高引/顶会 | `[FRONTIER]` |
| 🔗 综述文献 | 标题含 survey/review/综述 | `[REVIEW]` |
| ⚡ 争议文献 | 后续文献中频繁被反驳/讨论 | `[DEBATE]` |
| 🎯 最相关文献 | 标题与用户主题高度重合 | `[CORE]` |

## 四、雪球扩展（标准步骤，查全率保障）

> 方法详见 `modules/search-methodology.md` §四。T2/T3 强制；T1/T5 至少对
> `[FOUNDATION]` / `[REVIEW]` 文献执行。

对标记为 `[REVIEW]` 和 `[FOUNDATION]` 的文献执行双向滚雪球：
- **后向**：读其参考文献列表 → 捞漏网的早期奠基文献；
- **前向**：查其被引（Semantic Scholar `citations` 字段 / Google Scholar"被引"链接）→ 捞最新跟进；
- 雪球候选走相同纳排标准，来源标记 `snowball`，数量记入 `search_log.md`（备注"雪球"）；
- **终止条件**：连续两轮新增相关文献 < 3 篇（饱和），记录"雪球已饱和"。

## 四-A、筛选决策留痕（全类型，回答"为什么选这些"）

> 老师的核心质疑——"为什么选择这些文献"——必须能逐篇回答。

每篇文献的筛选决策写入 `{project_path}/outputs/lit-review/screening_decisions.md`：

| 文献ID | 决策 | 阶段 | 理由（一句话） |
|--------|------|------|---------------|
| lit_001 | 纳入 | 标题摘要筛 | 命中块A+块B，实证研究 |
| lit_002 | 排除 | 标题摘要筛 | 商业产品软文，非学术来源 |
| lit_003 | 排除 | 全文筛 | 付费墙且无 OA 替代 |

- **T2 / T3**：全量记录（纳入+排除+理由），作为 PRISMA 流程图数据源；
- **T1 / T5**：排除类至少记录**大类原因**（不相关 / 非学术 / 不可得 / 重复），
  纳入文献记录一句话纳入理由——不需要 PRISMA 全流程，但"为什么选了这 N 篇"必须能回答；
- **T4**：记录计量清洗决策（合并/修正规则）替代相关性筛选记录。

---

## 四-B、按 review_type 分支的筛选要求

- **T1 / T5**：按主题聚类即可（第二节），保留代表性文献，不强制逐篇记录排除理由。
- **T2 / T3**：必须产出 **PRISMA 流程数据**——记录每轮（标题摘要筛 / 全文筛）的纳入数、排除数、排除理由（与 P2 的 `excluded_reason` 对齐）；T2 额外标注偏倚风险等级，供 P5 / P7 使用。此数据是 P5 生成 PRISMA 流程图、P7 核查完整性的依据。
- **T4**：不做传统"相关性筛选"，改为**计量清洗**（去重、合并同名、修正字段），保留全部可计量文献；筛选结果即清洗后的全量数据集。

## 五、Hard Stop：选文确认（用户逐篇确认后才进 P4）

> 这是"为什么选这些文献"的人工把关点：助手给出清单与逐篇选取理由，
> 用户确认或修改，**未获明确确认不得推进 P4**。

### 5.1 选取理由的口径（按 review_type 分流）

理由格式统一为「**类型专属维度 + 可验证事实**」，禁止空洞理由
（"重要文献""被引很高""与主题相关"均无效，等于没给理由）：

| 类型 | 理由维度 | 合格理由示例 | 无效理由（会被审稿人质疑） |
|------|---------|-------------|--------------------------|
| **T1** 叙述性 | 主题覆盖（每个子主题≥1篇代表）+ 路线代表性（开创之作或最优实现）+ 时间代表性（奠基+前沿两端都有）+ 权威出处 | "轻量化部署路线代表（子主题A1唯一覆盖），2024 顶会" | "很经典""大家都引"（经典≠与综述问题相关）；只引支持预设结论的文献 |
| **T2** 系统综述 | **逐条对照纳排条款**（引用条款编号），排除项均不触发；纳入数与 PRISMA 流程图一致 | "命中 I2+I3，排除项 E1–E4 均不触发" | "作者认为相关"（主观词在 T2 致命）；数字与流程图对不上 |
| **T3** 范围综述 | 概念/证据图谱覆盖 + 证据类型多样性（实证、综述、灰色文献都覆盖）+ 服务缺口识别 | "填补'实验教学'概念节点，灰色文献（行业标准）代表" | 按结论有用性筛（画地图不是筑墙）；预设质量门槛过滤 |
| **T4** 文献计量 | **计量清洗决策**（去重/合并/修正规则），规则客观可复现，不按相关性挑 | "去重后保留唯一记录，DOI 已修正" | "更重要所以保留"（按偏好留删=操纵样本）；"手工剔除异常值"无规则 |
| **T5** 批判性 | 论点支撑（每篇对应一个明确论断）+ **反方代表强制在场**（争议点双方文献都有）+ 争议里程碑 | "作为'端侧算力瓶颈论'的反方证据纳入" | 引文全是"同意我的人"（选择性引用）；批评某方法却不引其原始文献 |

### 5.2 展示格式

向用户展示：
- 各轮筛除/保留数量（T2/T3 附 PRISMA 漏斗数）
- 主题聚类树
- **最终纳入清单，逐篇（或逐组）附上表口径的选取理由**，核心文献带标记
- 红旗自检结果：自引/同团队占比 >20%？来源单一（全预印本/全中文）？
  文献年龄断层？孤儿文献（清单有、正文不会讨论）？——命中须说明或整改

### 5.3 用户选项（四选一，均可组合）

1. **全部确认** → 记录确认，放行 P4；
2. **删除某篇** → 用户给或助手补一句删除理由，记入 `screening_decisions.md`
   （决策阶段=「用户确认」），若删后某子主题失去覆盖，**提示用户补搜**；
3. **补充文献** → 用户给标题/DOI，走 P2 补搜 + 相同纳排标准 + 雪球，再回到本确认点；
4. **调整理由** → 用户对某篇理由不满意（如"理由不成立""换代表文献"），
   按该类型口径重述或替换文献，再确认。

### 5.4 留痕

用户的所有增删与确认都写入 `screening_decisions.md`（决策阶段=「用户确认」），
保证"最终清单为什么长这样"有据可查；未确认前 HUD `literature.final_selected`
不得写入。
